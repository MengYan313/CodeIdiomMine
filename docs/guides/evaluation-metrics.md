# 代码习语评价指标规范

- 状态：**当前实现规范，已固定**
- 版本：CIM 5.2
- 生效日期：2026-07-18
- 适用范围：`src/evaluation/`、评价 JSON、离线测试与后续实验记录

本文是 CodeIdiomMine 当前评价指标的项目级规范，也是指标名称、计算口径、聚合方式和解释边界的事实来源。`docs/research/` 只提供研究背景，不定义当前工程行为；源码实现、测试或其他开发文档与本文冲突时，应修正实现或相关开发文档，不应通过修改研究稿来迁就当前代码。

当前最终指标固定为两组、九项：

1. **仓库分布与复现**：`IC_macro`、`IC_micro`、`IC`、`ISP`、`F1`。
2. **习语库规模与结构**：习语种类数、平均聚类簇大小、平均跨文件支持数、`AvgAST`。

评价必须先输出每个仓库的结果，再输出仓库宏平均和必要的全局汇总。当前不使用排序指标，也不使用 Top-K 指标。后续只有在需求明确提出、公式与分母得到确认并补齐测试后，才能扩展最终指标集合。

## 1. 分类思路

两组指标回答不同问题，不能混合成一个无解释性的总分。

### 1.1 仓库分布与复现

这一组从测试区域观察习语库的外部表现：

- `IC_macro` 与 `IC_micro` 衡量习语实例能覆盖多少 AST 结构；
- `ISP` 衡量训练区域得到的习语种类能否在测试区域再次出现；
- 最终 `IC` 平衡函数级和节点级两种覆盖视角；
- `F1` 平衡最终覆盖率与集合复现率。

该组用于回答“习语是否广泛分布、是否具有复现性”，但不直接判断习语是否语义正确、质量优良或符合某个项目的编码规范。

### 1.2 习语库规模与结构

这一组描述产出的习语库本身：

- 习语种类数反映知识库规模；
- 平均聚类簇大小反映每类习语的实例支持强度；
- 平均跨文件支持数反映习语是否只集中在单个文件；
- `AvgAST` 反映习语实例的结构规模和粒度。

该组用于解释第一组结果。例如，高 IC 可能来自少数超大簇或大 AST 片段，习语种类数与簇结构可以帮助识别这种情况。频率、跨文件支持和 AST 规模都不是代码质量分数，不能单独证明某个簇是优质习语。

## 2. 统计对象与统一约定

### 2.1 仓库、函数和 AST 节点

对仓库 `r`，测试区域中所有非空函数 AST 的集合记为 `F_r`。函数 `f` 的可统计 AST 节点集合记为 `N_f`。

当前实现使用 Tree-sitter C++ 产生的深度优先 AST 列表。IC 的分母包含测试区域内每个非空函数 AST 的全部节点，而不是只包含候选节点。候选匹配仍受当前 C++ 候选类型和最小子节点数规则约束。

### 2.2 习语种类与习语实例

评价中的“种类”和“实例”必须区分：

- **习语种类**：一个评价记录代表一种习语。判断阶段通常对应一个被接受的聚类簇；合成阶段对应一个合成后的输出记录。
- **习语实例**：该记录 `source_infos` 中的每个代码片段都是该类习语的一个实例。

一个簇里的所有代码片段都属于该类习语，不能只计算聚类中心、中心最近点或代表实例。覆盖匹配、集合复现、簇大小、跨文件支持和 `AvgAST` 均应保留并利用完整 `source_infos`。旧产物没有 `source_infos` 时，评价器才退回单个 `info`，这种退回只用于兼容，不是推荐的数据契约。

### 2.3 匹配规则

默认留一仓库和项目内文件划分模式使用当前结构化词法匹配器：

- 保留 C++ 关键字、运算符和候选 AST 节点类型；
- 抽象普通标识符、数字、字符串和字符字面量；
- 将同一习语全部来源实例生成的签名视为该习语的可匹配变体；
- 测试节点匹配任一变体，即认为该习语在该位置复现。

当前匹配器不是参数化 AST 模板或 AST 反统一实现。其结果只能表示当前具体候选表示下的结构化复现。

模拟簇证据模式不运行上述泛化匹配，而是按文件和候选 `extent` 使用已知簇成员作为证据，以便独立检查指标公式和分子分母。

### 2.4 AST 覆盖并集

若同一函数中多个习语匹配的 AST 子树重叠，重叠节点只计一次。对函数 `f`，全部匹配子树的节点并集记为 `M(f)`。

候选范围必须使用 `info[3].extent`，即候选 AST 节点自身的范围；`info[2]` 是包含它的函数范围，不能用于候选覆盖或候选 AST 规模，否则会把整个函数错误计入习语。

## 3. 仓库分布与复现指标

### 3.1 IC_macro：函数覆盖率宏平均

先计算每个测试函数的 AST 覆盖率：

```text
coverage(f) = |M(f)| / |N_f|
```

再对仓库中的所有测试函数等权平均：

```text
IC_macro(r) = sum(coverage(f), f in F_r) / |F_r|
```

每个函数权重相同，因此大函数不会因为节点更多而自动获得更大权重。它反映“一个典型函数有多大比例的 AST 被习语覆盖”。

价值：

- 对仓库中大量短函数和少量超大函数较稳健；
- 适合比较习语在函数层面的分布广度；
- 可以避免单个大文件或大函数完全主导覆盖结果。

限制：极短函数和超大函数权重相同，不能单独表达全仓节点总量上的覆盖。

### 3.2 IC_micro：AST 节点覆盖率微平均

将所有测试函数的覆盖节点和 AST 节点分别求和：

```text
IC_micro(r) = sum(|M(f)|, f in F_r) / sum(|N_f|, f in F_r)
```

每个 AST 节点权重相同，因此节点更多的大函数对结果影响更大。它反映“测试仓库的全部 AST 节点中有多少被习语覆盖”。

价值：

- 直接对应全仓 AST 节点覆盖规模；
- 适合发现习语是否覆盖了大型实现区域；
- 与覆盖节点数、节点总数可以直接相互校验。

限制：若少数大函数覆盖较高，IC_micro 可能掩盖大量小函数没有匹配的事实。

### 3.3 IC：最终覆盖率

最终 IC 固定为两种覆盖率的算术平均：

```text
IC(r) = (IC_macro(r) + IC_micro(r)) / 2
```

该设计同时保留“函数等权”和“节点等权”两种视角，避免只采用其中一种造成系统性偏向。`IC_macro` 和 `IC_micro` 必须与最终 `IC` 一起报告，不能只输出合并后的数值。

### 3.4 ISP：习语集合复现率

对当前评价 fold，训练习语集合记为 `I_train(r)`。其中在测试区域至少匹配一次的习语种类集合记为 `I_reproduced(r)`：

```text
ISP(r) = |I_reproduced(r)| / |I_train(r)|
```

同一习语无论在测试区域出现一次还是多次，分子中只计一个种类。一个习语的任一 `source_infos` 变体匹配成功，即认为该习语复现。

在文件划分模式中，只有训练文件中至少含一个实例的习语才能进入 `I_train(r)`；没有训练实例的簇不应进入 ISP 分母。

价值：

- 衡量训练阶段所得习语集合的可复现性；
- 防止只通过少数高覆盖习语获得较高 IC，而大部分习语从不复现；
- 与 `matched_idiom_count/evaluated_idiom_count` 可直接审计。

限制：虽然历史名称包含 Precision，但 ISP 不是人工正确率，也不表示代码质量。它只表示集合在独立区域的复现比例。

### 3.5 F1：覆盖—复现平衡

F1 固定使用最终 IC，而不是单独使用 IC_macro 或 IC_micro：

```text
F1(r) = 2 * IC(r) * ISP(r) / (IC(r) + ISP(r))
```

当 `IC=0`、`ISP=0` 或两者之和为 0 时，F1 记为 0。

价值：

- 同时约束覆盖率和集合复现率；
- 一侧很低时不会被另一侧的高值完全掩盖；
- 适合用一个辅助值观察两种能力是否均衡。

限制：F1 只是本组指标的平衡统计，不能替代 IC、ISP 的原始值，也不能与习语库规模指标继续加权成“总质量分”。

## 4. 习语库规模与结构指标

对仓库 `r` 的输出习语集合 `I_r`，习语 `i` 的完整实例集合记为 `S_i`。

### 4.1 习语种类数

```text
idiom_type_count(r) = |I_r|
```

判断产物按被接受的簇记录计数，合成产物按最终合成记录计数。该指标表示知识库实际包含多少种习语，而不是代码片段实例总数。

价值：反映方法的产出规模，并为平均簇大小、跨文件支持和 AvgAST 提供类型级分母。

限制：种类多不等于质量高；重复、过度细分或噪声簇都可能增大该值。

### 4.2 平均聚类簇大小

每种习语的簇大小是其完整实例数：

```text
cluster_size(i) = |S_i|
avg_cluster_size(r) = sum(cluster_size(i), i in I_r) / |I_r|
```

所有 `source_infos` 成员都参与计数。兼容旧产物且缺少来源列表时，可退回记录中的 `cnt`，但新产物必须以完整实例列表为准。

价值：衡量一种习语平均有多少代码片段提供支持，可以辅助区分偶发模式与高频模式。

限制：大簇可能来自模板过宽、重复代码或特定项目惯例；该值不是内聚度，也不是习语正确率。

### 4.3 平均跨文件支持数

对每种习语，统计其全部实例涉及的不同源码文件数：

```text
file_support(i) = |{file(x) : x in S_i}|
avg_cross_file_support(r) = sum(file_support(i), i in I_r) / |I_r|
```

同一文件中无论有多少实例，只计一个文件支持。当前字段来源是 `source_infos[*][1]` 对应的 C++ 文件路径。

价值：

- 判断模式是否跨越多个文件，而不是集中在单个局部实现；
- 与平均簇大小结合，可以区分“同一文件大量重复”和“多文件稳定复现”；
- 为后续分析仓库内通用性提供直接证据。

限制：文件划分受仓库组织方式影响；一个巨型文件和多个细粒度文件不可简单视为相同工程结构。该指标当前只统计跨文件，不推断跨模块或跨仓库支持。

### 4.4 AvgAST：习语结构规模

实例 `x` 的 AST 子树节点数记为 `A(x)`。优先读取解析阶段保存的 `subtree_size`；旧产物缺失时，使用候选 `extent` 在原始函数 AST 中重建完整子树大小。

先在每种习语内部对所有可测实例求平均：

```text
type_avg_ast(i) = sum(A(x), x in measurable(S_i)) / |measurable(S_i)|
```

再对所有具有可测 AST 规模的习语种类做宏平均：

```text
AvgAST(r) = sum(type_avg_ast(i), i in measurable(I_r)) / |measurable(I_r)|
```

这种“两层平均”保证每个簇的全部实例参与计算，同时避免单个超大簇仅因成员数量多而完全主导 AvgAST。无法从成员恢复 AST 规模时，可使用记录的 `avg_subtree_size`；仍不可测的种类保留在习语种类数中，但不进入 AvgAST 分母，并通过 `ast_measured_type_count` 暴露实际分母。若没有任何可测种类，AvgAST 记为 0。

价值：

- 描述习语的平均结构粒度；
- 辅助判断系统更偏向短语句模式、复合块还是大函数区域；
- 与 IC 联合解释时，可识别高覆盖是否主要由大 AST 片段造成。

限制：AST 节点数受解析器语法树设计影响，不能直接表示源码行数、圈复杂度、语义完整性或维护成本。

## 5. 按仓库输出与多仓库聚合

### 5.1 输出顺序

评价结果必须按以下顺序解释：

1. 逐仓库输出两组指标；
2. 输出仓库宏平均；
3. 输出必要的全局汇总及其分子、分母。

仓库宏平均用于“仓库等权”比较，全局汇总用于观察所有函数、节点或习语种类合并后的总体规模。两者权重不同，必须分别命名，不能把全局值标成宏平均。

### 5.2 仓库宏平均

设参与评价的仓库集合为 `R`。对第一组每个指标 `m`：

```text
repository_macro(m) = sum(m(r), r in R) / |R|
```

其中仓库宏平均 F1 是各仓库 F1 的算术平均，不使用宏平均 IC 和宏平均 ISP 再计算一次。

第二组也按仓库等权平均：

- 习语种类数表示“每个仓库平均包含多少种习语”；
- 其余三项表示相应仓库指标的算术平均。

### 5.3 必要的全局汇总

全局统计使用原始分子、分母重新汇总：

```text
global.IC_macro = 全部仓库 function_coverage_sum / 全部仓库 function_count
global.IC_micro = 全部仓库 matched_node_count / 全部仓库 total_node_count
global.IC       = (global.IC_macro + global.IC_micro) / 2
global.ISP      = 全部仓库 matched_idiom_count / 全部仓库 evaluated_idiom_count
global.F1       = harmonic_mean(global.IC, global.ISP)
```

习语库全局汇总为：

```text
global.idiom_type_count          = 各仓库习语种类数之和
global.avg_cluster_size          = 全部实例数 / 全部习语种类数
global.avg_cross_file_support    = 全部类型文件支持数之和 / 全部习语种类数
global.AvgAST                    = 全部可测 type_avg_ast 之和 / 全部可测习语种类数
```

因此，仓库宏平均与全局值可能不同。例如，大仓库在全局 IC 中拥有更多函数或节点权重，但在仓库宏平均中仍只占一个仓库权重。

## 6. 空集合、舍入与可审计字段

### 6.1 空集合

- 没有测试函数时，`IC_macro`、`IC_micro` 和 `IC` 均记为 0；
- 没有训练习语时，ISP 记为 0；
- IC 或 ISP 为 0 时，F1 记为 0；
- 没有习语种类时，四项习语库规模与结构指标均记为 0；
- 没有可测 AST 规模的习语种类时，AvgAST 记为 0。

这些 0 表示没有可用分母或没有匹配证据，不应自动解释为方法质量为零。报告时应同时检查原始计数。

### 6.2 舍入

- IC、ISP、F1 及簇/文件支持平均值在 JSON 中通常保留 4 位小数；
- AvgAST 和兼容的 AST 规模统计通常保留 2 位小数；
- 原始计数保持整数；
- 汇总时应使用评价器保存的分子、分母或未格式化内部值，不应从论文表格中截断后的字符串反推。

### 6.3 必须保留的审计信息

`eval.json` 除最终指标外，还应保留足以核对公式的字段：

- `matched_node_count`、`total_node_count`；
- `function_count`、`function_coverage_sum`；
- `matched_idiom_count`、`idiom_count` 或 `evaluated_idiom_count`；
- `total_cluster_instances`；
- `total_cross_file_support`；
- `ast_measured_type_count`。

这些字段是分子、分母或诊断信息，不属于新增的最终指标。

兼容字段 `avg_idiom_size`、`median_idiom_size` 和 `idiom_size_iqr` 可以继续存在于 JSON 中用于旧接口和代表实例诊断，但不属于本文固定的九项最终指标。最终结构规模应以 `AvgAST` 为准。

## 7. 评价模式及其结论边界

### 7.1 `leave_one_project_out`

默认模式。每次把一个仓库作为测试仓库，其他仓库的习语产物作为训练习语集合，同一集合同时计算 IC 与 ISP。

该模式用于观察具体候选表示的跨仓库复现。当前系统尚未实现参数化 AST 模板，因此严格跨仓库数值偏低可能来自命名、API 和代码结构差异，不能在没有证据时归因于指标错误。

### 7.2 `within_project_file_split`

按稳定哈希把同一仓库的文件划分为训练文件和测试文件，并只使用训练文件中的来源实例构造匹配变体。

如果聚类或前序阶段曾使用全仓数据，该模式仍可能存在数据泄漏，只能作为工程诊断。正式独立实验必须先冻结文件或克隆族划分，再仅在训练区域重新执行解析后的挖掘阶段。

### 7.3 `mock_cluster_file_split`

该模式只允许带 `mock_provenance` 的模拟产物。它将冻结簇的全部成员按文件划分，并用候选 `extent` 作为已知匹配证据。

用途仅限于：

- 检查是否错误地只使用聚类中心；
- 检查候选范围是否误用函数范围；
- 检查重叠节点并集、IC/ISP/F1 公式；
- 检查仓库宏平均和全局汇总；
- 检查结果数值是否因实现错误异常偏低。

因为 DBSCAN 聚类在文件划分前已经观察完整仓库，该模式不能估计未知测试集泛化能力，也不能作为模型质量或论文实验结果。

现有 `clusters.top100.json` 只可作为已经冻结的模拟语料标签清单。构造器只读取 `project` 和 `label`，忽略历史 `rank`；评价产物不保存 `rank`，也不计算排序、Top-K、Precision@K 或 Recall@K。

## 8. 指标价值与联合解读

| 观察组合 | 可支持的解释 | 不能直接推出的结论 |
|---|---|---|
| IC_macro 高、IC_micro 高 | 函数层面和节点总体上都存在较广覆盖 | 习语一定正确或值得复用 |
| IC_micro 明显高于 IC_macro | 覆盖可能集中在少数大函数或大 AST 区域 | 小函数完全没有价值 |
| IC_macro 明显高于 IC_micro | 多数函数有匹配，但匹配片段可能较小 | 习语粒度一定合理 |
| IC 高、ISP 低 | 少数习语覆盖较广，但多数训练习语没有复现 | 系统拥有高集合精度 |
| IC 低、ISP 高 | 很多习语能复现，但单次覆盖区域较小 | 习语没有复用价值 |
| 平均簇大、跨文件支持低 | 实例可能集中在少数文件 | 簇一定是重复噪声 |
| 平均簇大、跨文件支持高 | 模式在仓库内分布较广 | 模式一定跨仓库通用 |
| AvgAST 高且 IC 高 | 覆盖可能由较大结构片段贡献 | 语义一定更完整 |
| 种类数高但 ISP 低 | 习语库可能过度细分或包含长尾模式 | 所有未复现习语都是错误习语 |

最终报告应同时展示两组指标和必要分母。不能只选择最有利的一项，也不能把不同单位的指标任意相加。

## 9. 不属于当前指标的结论

当前九项指标不依赖全仓习语 Ground Truth，因此不能计算或声称：

- 全仓习语 Recall；
- 人工有效习语 Precision；
- 语义正确率、编译通过率或运行时正确率；
- 代码异味识别准确率；
- 模板参数化质量；
- 跨模块或跨仓库支持数；
- 排序质量或任何 Top-K 指标。

如需其中任何一项，应作为新的评价需求单独设计数据、分母、实现和验证，不能复用现有指标名称表达不同含义。

## 10. 变更控制与实现映射

当前指标集合已经固定。后续变更应满足以下条件：

1. 用户明确提出新增或修改需求；
2. 说明指标回答的问题及其与现有指标的非重复价值；
3. 固定统计对象、分子、分母、聚合层级、空集合和舍入规则；
4. 明确是否需要独立数据划分、人工标签或外部工具；
5. 为公式、全成员计入、重叠去重、仓库宏平均和全局汇总增加确定性离线测试；
6. 更新本文、评价 JSON 契约、测试指南和本地实验记录；
7. 保持旧字段兼容，或明确给出 schema 迁移方案。
