# C++ 数据集 Parser 优化与回归记录

## 目标与边界

本轮先在 27 个固定 commit 候选上运行原始 Parser 基线，再根据真实证据实施通用修改。修改只涉及源码发现、路径身份、审计与单项目可复现入口；没有调整 Tree-sitter C++ 后端、函数筛选规则、候选阈值、四列 pickle Schema、Agent、提示词、embedding 或 DBSCAN。

目标项目始终按零构建解析处理。本轮没有执行任何候选仓库的 CMake、Make、Meson、Bazel、Autotools、代码生成器、测试或程序。

## 基线

基线使用 CodeIdiomMine commit `ae1b62d523af7a7c9a97cfb0b661215787c67dac`，逐项目证据位于 `outputs/dataset-experiment/baseline/`。

| 指标 | 基线 |
|---|---:|
| 候选项目 | 27 |
| 扫描文件 | 11,636 |
| 有效代码行 | 1,894,674 |
| 文件级成功率 | 100% |
| 异常文件 | 4,238（36.42%） |
| ERROR 节点 | 60,005 |
| MISSING 节点 | 26,693 |
| 可靠 AST 字节覆盖率 | 82.13% |

| 候选 | 322,039 |
| 无函数输出文件 | 3,063 |

基线暴露了四类可泛化问题：

1. 扫描范围混入大量 test、example、benchmark、vendor、generated 与构建目录，同时旧规则也可能因字符串子串误伤正常路径；
2. 输入扩展名集合不完整，遗漏 `.c`、`.hh` 和 `.c++`；
3. 符号链接可能让同一实体以多个路径进入语料，且路径越界没有集中诊断；
4. `cppFile` 的 basename 身份不足以区分不同目录中的同名文件，审计与 AST 的源码身份也需要统一为仓库相对路径。

## 实施的通用修改

### 确定性源码发现

`FileScanner` 现在使用大小写不敏感的标准 C/C++ 扩展名集合，并按完整目录段实施排除规则。`contest/` 和 `latest.cpp` 等包含 `test` 字符串但不是测试段或测试命名的路径会被保留。目录和文件遍历均按仓库相对路径排序。

扫描器排除常见构建、缓存、第三方、生成、测试、示例与基准目录；排除测试命名、protobuf/gRPC、`moc_`、`ui_` 等常见生成文件；不跟随符号链接，并把符号链接、越界路径和各类排除计数写入审计。

### 稳定路径身份

`cppFile`、AST `source_path` 和审计排序键统一采用项目仓库相对 POSIX 路径。不同目录下的同名文件不再覆盖或混淆；绝对路径不进入正式 pickle 标识。Parser 仍保留稳定内容哈希与原始字节坐标。

### 可复现单项目入口

`repo2data` 增加可重复的 `--project <精确目录名>` 参数。项目名必须是单个安全目录名、必须在输入根目录下真实存在，路径穿越会直接失败。未传该参数时仍保持解析全部项目的兼容行为。

正式数据集为 26 个项目；被淘汰的 GSL 在基线和最终阶段均没有标准扩展名核心文件，因此下表的数值与 27 候选汇总相同。

文件、函数和候选减少主要来自明确排除非核心目录，不能解释成函数抽取能力下降。部分项目因补齐扩展名或取消子串误伤而增加核心文件，例如 btop、cereal、EnTT、Ninja、React Native 与 Yoga。

可靠 AST 字节覆盖率下降必须如实保留：优化后语料更集中于部分宏密集或聚合核心头文件，cpp-httplib、nlohmann/json、simdjson 与 Yoga 的项目级覆盖率低于 0.5。当前修改没有为提高单一分数而改写恢复算法或静默删除这些核心文件；这些项目被标记为“条件保留”，逐文件错误仍完整保留。

## 确定性与产物完整性

在 Parser 源码 SHA-256 `48064d7996bba06da13cbb83672a528ad4c50b794caef75b6fd40ae47ba288f3` 下，代表性小型头文件项目 CLI11 和大型应用 qBittorrent 各独立运行两次：

| 项目 | 两次确定性摘要是否一致 | SHA-256 |
|---|---|---|
| CLI11 | 是 | `ab02ad38b1a1a54ee29c7d665c05ee876870f385b5ba72490798f5d0e93da7fd` |
| qBittorrent | 是 | `f85bc022c2612941f7c08e289979b3299fbfc34d518be2ea97235dd2aa378965` |

摘要覆盖固定 commit、Parser 指纹、源码清单与内容哈希、相对路径顺序、逐文件实体/候选/错误统计和路径证据，不包含运行时长或峰值内存。重复运行产物位于 `outputs/dataset-experiment/final-repeat/`。

26 个正式项目均另外通过标准 `repo2data` 入口生成 `dataset.pkl` 和 `dataset.audit.json`。清单校验重新读取这些文件并确认：

- pickle 列严格为 `project`、`cppFile`、`func_ast`、`func_src`；
- 每份 pickle 只包含目标项目；
- `cppFile` 均为唯一、非绝对、无 `..` 的仓库相对路径；
- 审计扫描文件数和函数数与独立分析结果逐项目一致；
- 全部 JSON 可解析，文件记录完整，解析失败数为 0。

## 测试

新增回归测试覆盖：

- `.c`、`.hh` 与现有 C++ 扩展名；
- 目录段排除与 `contest/latest.cpp` 非误伤；
- 测试文件、生成目录、vendor、build 和符号链接排除；
- 同 basename 的不同目录文件保持唯一；
- AST 与 pickle 使用相同仓库相对 POSIX 路径；
- 审计保存扫描诊断；
- `--project` 的精确选择与路径穿越拒绝。

最终验证命令和结果记录在 `local-baseline.md`。逐项目定量结果见 `../research/cpp-dataset-project-audit.md`，完整机器可读证据见 `../research/cpp-dataset-manifest.json`。
