# 阶段2 Embedding 与聚类验收规范

## 结论

当前阶段2可以结束，验收状态为“通过，但保留逐仓质量警告”。这里的“通过”只
表示 Embedding 可以稳定支撑密度聚类，DBSCAN 产生了数量充足、未塌缩且头部
结构质量合理的候选簇，可以进入后续多重可信门控；不表示每个簇已经是最终代码习语。

以下阈值是阶段交付的验收参考线，只用于说明现有产物是否足以进入下一阶段，
不是贝叶斯优化的目标函数，也不用于反向选择算法或参数。

## Embedding 合理性

Embedding 采用四项硬门槛：

| 指标 | 门槛 | 当前结果 |
| --- | --- | --- |
| 候选—向量对齐 | 26/26 仓库计数一致 | 通过，共 233,912 条 |
| 向量合同 | 全部为 CPU `float32`、`1×768` 且有限 | 通过 |
| 非零向量 | 每条向量范数大于 0 | 通过，全局最小范数 17.95 |
| 确定性 | 重复生成的源码、元数据和向量语义摘要一致 | 26/26 通过 |

这些指标证明 Embedding 没有丢失、错位、数值异常或重复运行漂移。聚类使用余弦
距离，因此原始向量范数的绝对差异不会直接改变邻域关系。Embedding 是否对本
任务有用，则由下游是否能形成未塌缩、跨文件且头部结构合理的簇共同验证。

## 聚类有效性

| 指标 | 门槛 | 当前结果 |
| --- | --- | --- |
| 产物合同 | 26/26 七列 Schema 有效 | 通过 |
| 有效簇大小 | 所有保留簇大小至少为 2 | 通过 |
| 逐仓覆盖率 | 50%～80% | 60.16%～74.57% |
| 最大簇占比 | 每仓不超过 15% | 最大 10.85% |
| 跨文件复现 | 每仓至少 1 个跨文件簇 | 最少 6 个，共 12,719 个 |

正式 DBSCAN 得到 31,965 个有效簇，覆盖 156,436 个候选，微平均覆盖率
66.88%，平均/中位簇大小为 4.89/2。以上指标证明结果既不是“几乎全是噪声”，
也没有退化为少数巨型簇，并且保留了足够的仓库内复现候选。

## 头部候选簇质量

头部质量同时检查每仓 Top100 与 `Top100 ∩ Top20%`。结构代理要求代表代码具有
一定 AST 规模、簇内源码不完全相同且至少跨两个文件。它不使用人工标签，也不
替代后续语义判断。

| 指标 | 门槛 | 当前结果 |
| --- | --- | --- |
| Top100 非平凡代表率 | 至少 80% | 86.33% |
| Top100 源码变体率 | 至少 80% | 87.22% |
| Top100 纯重复率 | 不超过 20% | 12.78% |
| Top100 强习语结构代理率 | 至少 35% | 40.12% |
| Top100 排名折扣强代理率 | 至少 35% | 39.92% |
| `Top100 ∩ Top20%` 强代理率 | 至少 40% | 43.97% |
| Top100 代表 AST 子树均值 | 至少 50 个节点 | 68.27 |

因此，聚类的总体头部结果具有较高的非平凡比例、源码变化和结构规模，强代理也
确实出现在较高排名，而不是只在长尾出现。这足以证明阶段2输出是适合后续筛选的
高质量候选集合。

## 警告与结束条件

`cli11`、`concurrentqueue`、`cpp-httplib`、`entt`、`magic_enum`、
`simdjson` 和 `uwebsockets` 的 Top100 存在纯重复偏高或强结构代理偏低现象。
这些仓库应在后续多重可信门控时优先执行重复、跨文件和语义完整性过滤，但不能使用
下游结果反向重调阶段2参数。

阶段2据此冻结：继续保留 DBSCAN 单一正式算法、当前逐仓参数、最终
`clusters.pkl` 与校验和。后续若要证明“最终习语质量”，应依次执行单簇规则/LLM
验证、关联闭环融合、人工抽查或独立标签评价；这些问题属于后续阶段，不是重新开启
Embedding 或聚类调参的条件。
