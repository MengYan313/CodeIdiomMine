# Agent 系统

LLM 只参与阶段三和阶段四。编排代码负责准备当前源码上下文、发送强类型消息、校验结构化结果并持久化位置式 checkpoint。

## 阶段三

单个候选簇依次经过：

1. 离线合同和低价值过滤；
2. 从完整成员统计中提出仅针对局部变量、参数和低语义字面量的受约束抽象；
3. 语义与复用价值审查，语义 Agent 只能批准已有提案；
4. 习语类型归类；
5. 独立异味审查。

上下文由项目目录、仓库相对文件路径和源码范围直接读取，并同时进入语义与异味请求。路径或范围无效时拒绝当前簇，不用内容哈希做身份判断。上下文只核验代表代码的含义和边界，不把相邻操作算入输出代码段。单个完整语句、仓库专属模式和同文件多位置重复都可以构成习语；动作数量、代码长度和目录类型不直接参与裁决，跨文件与其他支持证据只通过规则分或复用分进入一次业务总分。API调用目标、成员、字段、类型和关键运算符不参与抽象。

## 阶段四

阶段四从已接受簇的完整成员位置发现同一区域共现。规划 Agent 对每个区域调用一次，返回有限个有明确数据、控制、生命周期或错误处理关系的计划；相同候选集合跨区域只执行一次，随后每个计划独立组装、复核、分类和异味审查。合成代码必须能在已核验上下文中定位，必须不同于每个单独来源并增加组合语义；复核或异味审查中的阻断问题直接否决。最终 `accepted` 是全部阶段3基础习语与去重后新增合成的并集，`synthesized` 只保存新增项；来源候选只作证据，不伪装成合成实例。

## 基础设施

- Agent 继承 `src.agents.base.BaseRoutedAgent`。
- LLM 客户端直接由 `src.llm.client.create_model_client` 创建。
- 结构化响应保留一次 JSON 修复和有限重试。
- Runtime 始终使用 `start -> try/finally -> stop`。
- SQLite checkpoint 只保存处理位置和结果；`--resume` 跳过已完成位置。

业务 Agent 不自行加载 `.env`、实现重试、创建第二套 JSON 解析器或复制日志配置。
