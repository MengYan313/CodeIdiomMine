## 摘要

代码习语是开发者在特定语言和工程环境中反复采用的、具有明确语义且可复用的细粒度代码模式。高质量代码习语可以服务于代码理解、代码推荐、单元测试生成和编程规范检查。然而，现有方法往往依赖预定义规则或纯结构频率，难以同时兼顾候选覆盖、非连续语义关系、实现成本和工具可移植性，也难以区分“高频代码”与“值得复用的优质习语”。针对上述问题，本文将 CIMAS-CPP 组织为四阶段流水线：阶段1完成数据采集与清洗、AST构建与进阶处理、双轨代码片段抽取和元数据组装，其中轨道A保留语句级、区域级和函数级的大规模基础候选，轨道B只对存在明显跨边界 Def-Use、控制或显式资源配对关系的候选进行有界扩展，形成轻量 C++语义依赖链（Lightweight C++ Semantic Dependence Chain, L-CSDC）；阶段2融合代码语义嵌入、AST结构特征和可选依赖摘要，用密度聚类发现候选簇，并在冻结结果上执行仓库内保守归并；阶段3“多重可信门控”针对单个簇执行合同与低价值规则过滤，由规则基于完整成员筛出可能抽象的高频、结构对齐且低语义局部差异，再把代表代码、词法去重变体、四项簇统计、规则初判和全部提案交给语义/抽象 Agent 显式决定抽象或保持原样，同时由共享代码异味 Agent 独立审查，以业务评分和不可抵消的异味门禁完成知识定型，并把已接受结果归入目录化通用习语或仓库专属习语；阶段4“关联闭环融合”正式消费阶段3已定型产物，自动加载代表区域上下文，再针对多个候选习语执行关系规划、代码组装、当前结果复核和重新分类，并使用同一异味合同独立重审融合结果，把同一区域内互补习语组织为质量更高且可追溯的知识对象。最终习语库提供通用、专属和全量联合三种知识视图。阶段2到阶段4只保留不启动 Agent 的适配与严格阈值合同测试，不进入实际实验执行。阶段1以 Tree-sitter/C++ Adapter 提供免目标项目编译、免链接、免执行的全量基础路径，并可在已有安全编译信息时叠加 Clang 类型、符号和 CFG 能力；项目不可构建不会阻止基础候选、诊断和原文映射产生。全流程只使用静态源代码分析，不要求目标仓库成功编译、链接、测试或运行，也不依赖运行时插桩或复杂 LLVM IR 映射。评价以Haggis-CPP、纯LLM、规则聚类、IdioMine核心操作的C++近似和内部消融为对照，不穷举整个仓库中的真实习语；公共自动指标覆盖全部输出，人工除核验跨方法去重后的统一Top-$K$结果池外，还对异味过滤进行分层事后审计。本文所有预期效果均需由真实实验验证。

## 1 引言

大型软件仓库不仅包含具体业务实现，也沉淀了大量经过长期实践形成的编程知识。例如，资源申请与释放、空指针防护、错误码传播、作用域锁管理、智能指针构造和容器遍历等逻辑，往往以相似但不完全相同的形式反复出现。这些模式具有比单个语句更丰富的语义，同时又比设计模式更细粒度，适合被抽象为代码习语。

自动挖掘代码习语面临三个核心困难。

第一，**重复不等于习语，高频也不等于优质**。自动生成的 getter/setter、日志样板和偶然复制的代码同样可能高频出现；更严重的是，不安全资源管理、吞掉异常、错误的生命周期处理等反模式也可能因复制传播而高频出现。若系统只依据频率和相似性学习，会把坏习惯包装成可推荐习语，产生“自动学习并放大反模式”的风险。

第二，**C++结构复杂且上下文敏感**。宏展开、模板实例化、函数重载、RAII、隐式类型转换等机制使 token 相似度难以准确表达代码含义。若只分析词法序列，变量重命名和等价 API 调用可能掩盖同一习语；若只分析 AST 结构，又可能把语义不同但形状相似的片段聚为一类。

第三，**候选边界与候选产量需要平衡**。固定语句、区域和函数切片简单、稳定且产量高，但可能漏掉非连续的定义—使用、检查—处理或显式获取—释放关系；若要求每个候选都满足复杂依赖闭包，又会显著提高实现成本并过滤大量本可用于聚类的样本。IdioMine 的 DCC 说明依赖关系适合补充非连续片段，但本研究不把所有候选改造成依赖链，而采用“固定三层保底、轻量依赖链增量补充”的双轨设计。

为此，本文提出 CIMAS-CPP。核心思想是使用 Tree-sitter/C++ Adapter 提供零构建结构基础，并在安全可得时用 Clang 静态分析增量补充类型、符号和控制流语义；代码表征模型刻画功能相似性，密度聚类从大规模候选中发现自然簇，随后通过多重可信门控和关联闭环融合形成高质量习语库。本文不追求将全部工作交给大模型完成，而是让确定性工具负责大规模解析、规则门禁与验证，让表示学习和大模型集中处理结构规则难以覆盖的语义任务。阶段3的语义/复用价值评审与共享代码异味审查、阶段4的关系规划、组装与当前结果复核由职责隔离的 Agent 完成；阶段4上下文由编排层自动填充，并通过结构化输出、固定提示、确定性证据和人工标注集检验其可靠性。

本文拟回答以下研究问题：

- **RQ1：** 在不构造全仓习语Ground Truth的条件下，CIMAS-CPP最终输出能否比传统Haggis-CPP、直接LLM、简单AST频率基线和IdioMine核心操作的C++近似获得更好的覆盖—复现平衡、人工确认率、有效习语产量、静态有效性与成本权衡？
- **RQ2：** 在不降低基础候选产量的前提下，L-CSDC 能否补充固定三层切片漏掉的非连续 C++习语？零构建 Tree-sitter/C++ Adapter 基础路径与可选 Clang 增强之间存在多大质量、覆盖、采用成本和性能差异？
- **RQ3：** 每个仓库独立发现的全量习语在仓库内部具有怎样的跨文件支持、覆盖和分区复现性？其中目录化通用习语具有怎样的跨仓库类型分布与复用潜力，仓库专属习语又能否支持面向本项目的单元测试生成和编程规范识别等下游任务？
- **RQ4：** 多重可信门控能否区分高频代码与优质习语，并避免过度抽象及反模式泄漏？关联闭环融合能否相对独立习语产生可验证的质量增益？

本文的预期贡献如下：

1. 提出由“数据与片段表示—嵌入与聚类—多重可信门控—关联闭环融合”构成的四阶段 C++代码习语挖掘流水线，明确各阶段输入、输出和可替换边界；
2. 在阶段1提出产量约束的双轨候选抽取方法及“零构建 Tree-sitter/C++ Adapter 保底 + Clang 可选增强”的统一适配层，以“固定三层保底 + 轻量静态依赖增量增强”平衡候选规模、人工确认的非连续增量与工程成本，并使解析方法本身可迁移到无法完整构建的仓库；
3. 在阶段3提出多重可信门控，以“确定性规则门禁—可抽象位置初筛—精简簇视图语义抽象决策—语义/复用价值与异味独立审查—安全门控知识定型”避免机械抽象，并让拒绝抽象的合格习语保持原样；
4. 在阶段4提出关联闭环融合，以阶段3已定型产物为正式输入，分离自动代表区域上下文、关系规划、代码组装、当前结果复核与共享异味重审；阶段2只保留非执行合同适配；
5. 建立“目录化通用习语—仓库专属习语—全量联合视图”的知识组织合同，使已有目录类型能够跨仓库汇总和复用，同时保留项目特有及尚未目录化的开放发现；
6. 建立不依赖全仓习语Ground Truth的分层评价体系，以Haggis-CPP、LLM-Direct、规则聚类和IdioMine-CPP为端到端基线，以固定九项工程自动指标覆盖全部输出，并通过跨方法去重的Top-$K$盲评池获得最小人工质量证据。

## 2 背景与相关研究

### 2.1 代码习语与代码克隆的区别

代码克隆关注两个或多个代码片段在文本、语法或语义上的相似关系，而代码习语还要求模式具有明确意图、一定频率和可复用性。克隆检测可以提供候选，但不能直接判断某个重复片段是否代表优质实践；被复制传播的缺陷或反模式也可能形成高支持度克隆簇。本文把“高频相似”视为候选发现线索，把“不含明显代码异味、语义清晰、可参数化、可验证”作为进一步约束。

### 2.2 预定义习语识别

规则驱动方法先定义目标习语，再通过 AST 查询、数据流规则或重构规则匹配实例；Pythonic idiom自动重构是这一封闭规则路线的代表[E017]。这类方法精度高、解释性强，但只能识别已知模式，且为 C++模板、宏和项目特定 API 编写规则的成本较高。本文关注开放式发现，即不预先限定具体习语名称。

### 2.3 数据驱动习语挖掘

Haggis 使用概率树语法挖掘重复结构，展示了从语法树中自动发现代码模式的可行性[E002]。IdioMine 进一步从 Java 函数的 AST 和 CFG 构造精简 PDG，并以变量Def/Use和必要控制结构形成 DCC 子习语[E006]，能够覆盖部分非连续源码行。其代价是依赖构建和路径处理更复杂，且单变量链仍会漏掉无共享变量的关联片段。本文只吸收“静态依赖可补充非连续候选”的思想，以局部Def-Use、控制和显式API配对形成L-CSDC，并保留原三层候选作为主要输入。

### 2.4 代码表征与大模型辅助分析

预训练代码模型可以将变量命名、API调用和控制结构映射到连续向量空间，为语义相似检索和聚类提供基础[E037]。大语言模型还可以解释代码意图并判断片段是否具备完整语义。然而，直接让大模型扫描整个仓库成本高、可复现性弱。本文采用“静态分析和聚类初筛，大模型后置精判”的混合策略。

### 2.5 代码异味检测与反模式过滤

代码异味是潜在劣质设计或实现的风险信号。Fowler 的官方说明将其界定为通常指向更深层问题的表层征兆，并明确指出异味本身不必然等同于问题[E108]。相关研究已形成分类学、规则/度量检测、历史分析、机器学习和工具组合等路线。Mäntylä 等较早建立了代码异味分类[E040]，DECOR 将异味描述转化为可执行检测规则[E070]；系统综述则指出，异味定义具有主观性，检测器容易受规则阈值、覆盖范围和误报影响[E055][E079][E078]。经验研究还给出两项对本课题尤其重要的结论：异味可能在实体创建时即被引入并长期存留[E036]，但异味标签与维护成本之间并非在所有设置下都有稳定关系[E069]。因此，本研究把异味作为习语入库前的风险过滤依据，而不是把任何异味标签自动等同于缺陷或绝对低质量。

机器学习检测能够减少部分手工阈值依赖，但高度依赖标签、类别平衡和项目分布[E080][E078]。代码自然性研究发现缺陷代码总体上更可能表现出较高熵[E056]，却不能排除被复制传播后变得高频、可预测的坏习惯。正式会议论文 CLEAN++ 已利用 Clang AST 和编译数据库实现35类规则型异味[E028]，说明确定性 C++ 检测可作为本研究的对照和后续补充；其预定义类别和阈值也难以覆盖全部项目语境。LLVM 官方 Clang-Tidy 检查清单[E109]和 SEI CERT C++ 在线技术标准[E110]分别提供动态维护的工具规则与安全编码规范；二者不是异味检测效果论文，不能与 CLEAN++ 的实验结论混用。ASE 2024 的正式会议论文 iSMELL 显示，将 LLM 的语义能力与专家工具结合优于直接使用 LLM 的基线[E027]，支持本研究采用独立审查模块并保留未来工具融合接口。

基于上述证据，本研究当前实现由阶段3与阶段4共享的 Code Smell Review Agent 和17类固定 C++异味表，并将其明确视为需要实验验证的初始方案。两个阶段复用同一输入输出合同，但分别审查单簇代表和当前合成结果。Agent 只返回分类、严重度、置信度、可定位证据、影响与修复方向；确定性代码据此计算风险分。风险达到冻结阈值或分析失败时由独立门禁直接拒绝，异味不参与业务综合评分，也不能被高语义、复用或合成质量分抵消。实验必须与无审查、普通 LLM 附带异味判断、CLEAN++/其他静态规则比较，同时以独立人工审计报告总体、分阶段、逐类别的漏报和误过滤，避免质量过滤本身成为新的系统性偏差。

## 3 问题定义

给定一个 C++仓库集合 \(R=\{r_1,r_2,\ldots,r_m\}\)，每个仓库都是独立实验单元。静态分析器只从仓库 \(r\) 的全部合格源码中抽取候选片段集合 \(S_r\)，且 \(S_r\) 不与其他仓库的候选混合。每个候选片段 \(s\) 由以下信息组成：

\[
s = \langle code, ast, level, context, location, dep, backend, capability, source \rangle
\]

其中，`code` 和 `ast` 为源码与AST视图，`level` 为语句/区域/函数粒度，`context` 与 `location` 保存上下文和连续或非连续位置，`dep` 为可选的轻量静态依赖摘要，`backend` 标记 Clang 或 Tree-sitter，`capability` 标记该后端实际提供的类型、符号、CFG等能力，`source` 标记候选来自基础轨道还是增强轨道。缺失高级语义信息不会使基础候选失效。

目标是为每个仓库独立学习仓库内成立的习语集合 \(I_r\)。每个习语
\(i\in I_r\) 的实例都来自同一仓库 \(r\)，并包含参数化模板、实例集合、语义
描述、适用前置条件、质量分数和最终类型分类：

\[
i = \langle template, instances, intent, precondition, quality, classification \rangle
\]

已接受集合按当前目录版本划分为
\(I_r=I_r^{cataloged}\cup I_r^{specific}\)，且两者不相交。
\(I_r^{cataloged}\) 中的记录可按 `taxonomy_version + catalog_id` 与其他仓库
聚合为目录化通用知识；\(I_r^{specific}\) 中的记录以
项目和阶段内记录身份保持仓库作用域，并包含目录尚未收录的不常见通用习语。
全部指标的默认分析对象是二者并集，分层分析则分别使用两个子集。

一个有效习语应满足：

1. 在仓库中出现次数不低于频率阈值；
2. 实例具有相近结构或功能；
3. 模板能够通过参数实例化恢复合法 C++代码；
4. 习语具有可描述的编程意图；
5. 习语不应主要由项目特有常量或无意义样板构成；
6. 习语不包含经审查确认的明显代码异味或应当拒绝复用的反模式。

## 4 CIMAS-CPP 方法

### 4.1 总体流程

```text
C++仓库
  → 阶段1：数据采集/清洗 → AST构建与进阶处理
           → 双轨代码片段提取 → 元数据组装
  → 阶段2：Embedding嵌入 → DBSCAN聚类与代表簇筛选
  → 阶段3：多重可信门控
           → 单簇规则过滤 → 可抽象位置初筛 → 精简簇视图语义 abstract/keep
           → 语义/复用价值与代码异味审查 → 可信知识定型
  → 阶段4：关联闭环融合
           → 同区域关系分组 → 自动代表区域上下文 → 关系规划
           → 代码组装 → 当前结果复核/共享异味重审 → C++习语模板知识库
```

上述四阶段是 CIMAS-CPP 后续实现、实验、消融和论文写作的固定上位基准。阶段内部的解析器、嵌入模型、聚类器或Agent实现可以替换，但除非有新的实验证据和用户明确调整，不应改变“表示构建—聚类发现—多重可信门控—关联闭环融合”的阶段边界和顺序。为避免把本文机制降格为 IdioMine 式通用 ChatGPT 判断与合成，论文、图表和实验报告统一使用上述机制名称；源码包、CLI、artifact 和历史兼容字段仍沿用 `idiom_judgment`、`idiom_synthesis`、`judgment` 与 `synthesis` 等简洁工程标识，不据此改写方法学名称。

### 4.2 阶段1：数据与习语表示构建

本研究吸收 IdioMine“利用依赖补充非连续语义片段”的思想，但不以完整 PDG 或复杂路径分析替换原三层抽取。核心原则是：基础候选负责覆盖，轻量依赖候选负责增量创新；增强失败时仍保留基础候选，不能因为缺少高级语义信息而丢失样本。

#### 4.2.1 数据采集、清洗与解析后端

阶段1首先执行零构建解析：系统从固定 commit 的 C++仓库读取源码快照，不运行项目的配置、依赖安装、代码生成、编译、链接、测试或二进制。源码可读取即进入 Tree-sitter/C++ Adapter 基础路径；构建系统损坏、目标平台不匹配或第三方依赖缺失不得成为排除项目或文件的理由。逐文件记录解析状态、异常、未覆盖源码、恢复路径和原文范围，使“不可构建”与“不可解析”成为两个独立、可审计的概念。

系统可同时采集构建文件和已经存在且来源可信的 `compile_commands.json`，记录仓库、模块、文件路径、语言标准和编译数据库覆盖状态，但不为获得这些信息执行不可信构建逻辑。清洗阶段识别自动生成文件、第三方依赖、副本文件、空函数、机械 getter/setter 和极端长度片段；是否排除测试代码、示例代码和外部依赖必须作为显式配置，并保存清洗前后文件数、代码行数和排除原因，避免只保留最终百分比。

系统定义与具体解析器解耦的最小接口：AST节点类型、源码范围、父子关系、函数/块作用域、声明与使用位置、控制结构包含、调用表达式和原始类型文本。Tree-sitter/C++ Adapter 是所有语料始终执行的零构建基础后端；Clang 是具备可信编译信息的文件子集上的增强后端，用于量化类型、符号和 CFG 带来的增益，而不是决定源码能否进入主流程。

| 能力 | Tree-sitter零构建基础后端 | Clang可选增强后端 | 对候选的影响 |
|---|---|---|---|
| AST节点、源码范围、作用域 | 支持并保留原文 | 可校正或补充 | 三层基础候选始终可生成 |
| 语句/区域/函数识别 | 容错识别 | 语义 AST 校验 | 增强失败不删除基础候选 |
| 符号绑定与类型 | 名称和类型文本近似 | 按声明进行语义解析 | 影响聚类特征，不删除候选 |
| 控制关系 | 词法嵌套与语句顺序近似 | 可使用函数内 CFG | L-CSDC 精度可能提高 |
| 局部 Def-Use | 按名称+最近可见声明近似 | 按声明绑定 | 两种能力分别标记 |
| 宏、模板、隐式析构 | 保留可见语法、异常与恢复证据 | 可保留来源或补充标签 | 作为可选增强，不是主流程前提 |

每个候选保存 `backend` 和 `capability`。Tree-sitter基础路径覆盖完整语料并参与端到端实验；Clang增强在编译信息已安全可得的分层文件子集上评价语义质量增益，也可构成增强消融。不能把 Tree-sitter 的近似依赖写成 Clang 等价语义，也不能把 Clang 不可用写成文件没有候选。

#### 4.2.2 AST进阶处理与双轨片段抽取

AST构建后执行节点规范化、作用域恢复、函数/控制区域定位、源码范围映射和重复AST哈希。Clang后端额外恢复符号绑定、类型和函数内CFG；Tree-sitter后端使用名称、最近可见声明、词法嵌套和语句顺序近似。随后执行双轨抽取。

**轨道A：固定三层基础候选。** 该轨道延续原方案并始终执行：

- **语句级**：声明、赋值、调用、返回、抛出和显式资源操作；
- **区域级**：条件、循环、`try/catch`、lambda、连续调用链和词法作用域；
- **函数级**：长度受控的完整函数或方法。

该轨道只使用宽松、可复现的清洗规则去除自动生成文件、空函数、机械 getter/setter 和极端长度片段。它不要求依赖闭合、编译数据库完整或高级类型推断，从而保持与原方法相近的候选规模。三类候选是正式方法的一部分，而不是只作为基线。

**轨道B：选择性轻量L-CSDC。**

轨道B只在函数内使用静态源代码信息，对下列候选尝试增强：某个局部实体的定义和使用跨越基础边界；条件检查与后续处理被无关语句隔开；两个显式调用通过同一局部实体形成获取—使用—释放、加锁—解锁或打开—关闭关系；区域内部存在可由同名/同符号实体连接的非连续语句。

轻量依赖图只包含：

\[
G_f^{light}=(V,E_{order},E_{scope},E_{du},E_{ctrl},E_{pair})
\]

其中各边分别表示源码顺序、词法作用域、局部 Def-Use、控制包含/函数内CFG关系，以及由小型可配置 API 表识别的显式配对关系。初始配对表只覆盖少量可明确验证的 C/C++ 写法，例如 `fopen/fclose`、`malloc/free`、显式 `new/delete`、`lock/unlock`；配对必须作用于同一局部实体，规则表需版本化并在附录公开。Clang 后端可用符号绑定、类型和 CFG 提高精度；Tree-sitter 后端使用名称、最近可见声明、词法嵌套和语句顺序近似同一过程。

L-CSDC 从一条基础语句或区域出发，只补入最多两跳依赖、一个必要控制头和有限数量的关联语句；每个锚点最多生成一个增强候选，节点数不得超过对应函数的固定比例和绝对上限。系统不枚举执行路径，不进行动态分析、运行时插桩、动态链接、跨过程指针分析、LLVM IR/MemorySSA映射或全程序别名求解。指针别名、隐式析构、异常栈展开和未知调用副作用仅作为 Clang 可提供时的标签，不作为生成 L-CSDC 的强制条件。

#### 4.2.3 候选合并、元数据与产量约束

最终候选集合为：

\[
S_r=S_{base,r}\cup S_{enhanced,r}
\]

其中 \(S_{base,r}\) 为仓库 \(r\) 的轨道A全部基础候选，\(S_{enhanced,r}\) 为同一仓库轨道B成功生成的补充候选。两轨通过规范化源码、AST类型序列和位置集合联合去重；当增强候选与基础候选等价时，只合并元数据，不重复计数。L-CSDC 失败、依赖不确定或 Tree-sitter 出现语法恢复误差时，仅放弃该增强候选，不删除其来源基础候选。该集合不与其他仓库候选合并。

非连续增强候选按原始源码顺序重建，并补入最小控制头和作用域骨架；被省略的语句记录为 `<HOLE_n>` 元数据。每个候选组装统一元数据：源码/AST视图、粒度、基础/增强来源、仓库/文件/函数位置、解析后端、能力掩码、自由变量、类型文本、轻量依赖摘要、宏/模板标签、规范化哈希和清洗记录。L-CSDC 后续不要求每个候选都具有完整依赖图。

方法是否可行首先由候选产量和成本约束，而不是由图的复杂程度决定：

- 基础候选保留率相对原固定三层实现应接近100%；差异只能来自统一记录的清洗和去重规则；
- 不以依赖闭合度作为基础候选硬过滤条件；
- L-CSDC 增强候选数量、抽样边界有效率，以及最终形成的人工确认非连续习语增量单独报告；
- 报告每千行代码的解析时间、峰值内存、基础候选数和增强候选数；
- 若 L-CSDC 的抽样边界有效率或人工确认增量不足以抵消成本，则缩小适用触发器，而不是继续增加依赖类型。

因此，本研究把创新点进一步表述为“产量约束的依赖增强”。触发规则和预算通过独立 pilot、合成样本或预注册的分层人工候选审计冻结，不从正式仓库切出开发区域，也不使用最终 IC、ISP 或 F1 选择，使

\[
J=VNG_{norm}+\mu\,EVY_{sample}-\lambda\,EC_{norm}
\]

最大，其中 $VNG$（Validated Non-contiguous Gain）表示 pilot 审计中由轨道B独有贡献、且经人工确认的非连续最终习语数（按每万行代码归一化），$EVY_{sample}$ 只在分层抽样的L-CSDC候选上评价边界合理率。该目标同时要求基础候选全部进入合并前集合，并限制增强候选数不超过基础候选数的固定比例。它不假设能够获得全仓库习语真值，只用于在人工确认增量、抽样候选有效率和工程成本之间冻结可复现配置；正式仓库仍使用全部合格源码执行发现。

### 4.3 阶段2：Embedding嵌入与Cluster聚类

所有基础候选都计算语义向量 \(e_s\) 与 AST结构向量 \(a_s\)：

\[
z_s^{base}=\operatorname{Norm}([\alpha e_s;(1-\alpha)a_s])
\]

语义向量由预训练代码模型编码规范化源码得到；结构向量使用两个后端均能提供的 AST节点类型、路径、控制结构计数和调用/声明比例。这样即使只有 Tree-sitter，也可运行完整的候选聚类主流程。

对 L-CSDC 或 Clang 能提供额外信息的候选，再计算轻量依赖摘要 \(d_s\)，包括链长度、Def/Use数量、控制头数量、显式API配对和非连续跨度。依赖摘要作为附加特征或重排信号，并与 `capability` 掩码共同输入，避免把“缺失能力”误解为“依赖不存在”。论文通过消融决定该摘要是否进入最终表示；若收益不稳定，则只保留其作为候选来源元数据。

#### 4.3.1 密度聚类、代表实例与簇级元数据

当前正式方法采用工程基线 DBSCAN 发现密度簇，不要求预先指定习语数量，并把孤立片段作为噪声过滤。每个仓库的全部合格候选独立聚类；可以在仓库内部按语句、区域、函数和L-CSDC来源做预注册分层，但不得与其他仓库混合。正式算法在聚类前统一固定为 DBSCAN，不按仓库名或聚类后结果路由；HDBSCAN 只作为同口径阶段2对照。DBSCAN 参数使用目标函数改进的标准贝叶斯优化：代理模型固定为高斯过程（Gaussian Process，GP），采集函数固定为期望改进（Expected Improvement，EI），二者均不作结构改动；warm-start 只用于初始化已有观测。“改进”仅指用下述领域目标替换通用聚类目标，不得根据最终 IC、ISP、F1 或人工标签反复选择。

改进贝叶斯目标只保留三个与代码习语候选直接相关、且容易解释的无监督指标。令
\(R_r(\theta)\) 为参数 \(\theta=(\varepsilon,\textit{min\_samples})\) 产生的跨
文件有效簇数相对 warm-start 可行观测最大值的比例，\(H_r(\theta)\) 为按簇大小
排序后 Top100 中跨文件簇数的相对比例。令 \(c_r(\theta)\) 为聚类覆盖率，
\(m_r(\theta)\) 为最大簇占全部候选的比例。两个复现指标归一化为：

\[
R_r(\theta)=\min\left(1,\frac{N_{cross}(\theta)}
{\max(1,\max_{\phi\in\mathcal F_r}N_{cross}(\phi))}\right),\qquad
H_r(\theta)=\min\left(1,\frac{N_{top100,cross}(\theta)}
{\max(1,\max_{\phi\in\mathcal F_r}N_{top100,cross}(\phi))}\right),
\]

其中 \(\mathcal F_r\) 是当前仓库满足硬约束的 warm-start 参数观测集合；若有效
簇不足100个，Top100取全部有效簇。

密度平衡定义为：

\[
B_r(\theta)=\frac{1}{2}\max\left(0,1-\frac{|c_r(\theta)-0.65|}{0.15}\right)
+\frac{1}{2}\max\left(0,1-\frac{m_r(\theta)}{0.15}\right).
\]

贝叶斯优化最大化：

\[
J_r(\theta)=0.45R_r(\theta)+0.15H_r(\theta)+0.40B_r(\theta),
\qquad L_r(\theta)=1-J_r(\theta).
\]

其中覆盖率 \(0.50\le c_r(\theta)\le0.80\) 与最大簇占比
\(m_r(\theta)\le0.15\) 是可行性条件，不依赖加权分数抵消；违反条件的观测
不会成为最佳可行参数。该判定属于目标评价，不改变 GP 或 EI。搜索空间固定为
\(\varepsilon\in[0.0025,0.50]\) 的对数实数区间和
\(\textit{min\_samples}\in[2,4]\) 的整数区间。贝叶斯优化首先用已有参数结果
作为 warm-start；GP 根据观测学习 \(\theta\) 到 \(L_r\) 的关系，并预测目标均值
与不确定性；EI 相对当前最佳可行值计算期望改进，选择 EI 最大的下一组参数。
实际运行该组 DBSCAN、计算目标后，把新观测加入 GP，重复上述步骤，直到达到
预设预算或结果不再明显改善。该过程对每个仓库使用同一规则，不读取仓库名或
最终评价指标。

这些取值的理由保持简洁：`eps` 的上下界覆盖当前有效参数及原始默认值0.5，
采用对数尺度是因为较小 `eps` 区域更敏感；`min_samples=2` 与有效簇最小大小
一致，取值上限4覆盖当前全部最优组合且避免过度增加噪声；覆盖率目标0.65位于
50%～80%可行区间中部；最大簇占比15%用于阻止密度连锁形成巨型簇。权重0.45
优先保证跨文件候选供给，0.15关注后续优先分析的Top100，0.40用于约束聚类
密度平衡。

筛选前26仓实验不重新运行聚类：每仓既有18/33/45组完整参数结果直接作为改进
贝叶斯优化的 warm-start 目标观测。回放新目标后，最佳已观测可行参数与现有
冻结参数26/26一致，因此把该 warm-start incumbent 作为改进贝叶斯优化在当前
观测集和预算下的正式参数输出。新增聚类评估预算为0，故无需重复 DBSCAN；
若后续增加预算，再由 EI 继续提出参数并更新 GP。本文将现有参数表述为贝叶斯
优化得到的当前最优参数，但不声称它是连续搜索空间的理论全局最优。

冻结聚类完成后，再按统一的逐仓结构指标和具体簇语义执行数据集质量筛选。
`cpp-httplib`、`entt` 和 `simdjson` 不进入阶段3/4与论文主结果；该决定不改变
它们已经执行的 DBSCAN，不反向选择参数，也不使用最终 `IC`、`ISP`、`F1`、
人工习语标签或 LLM 结果。筛选证据见
`docs/research/cpp-clustering-quality-screening.md`。

对每个簇 \(C\) 计算候选质量：

\[
Q_r(C)=\lambda_f F(C)+\lambda_c Coh(C)+\lambda_r Rep_r(C)
\]

其中，\(F\) 表示仓库内出现频率，\(Coh\) 表示簇内内聚度，\(Rep_r\) 表示同一仓库的跨文件重复程度。该分数不含跨仓库信号，只衡量候选簇是否值得进一步审查，不代表代码质量；低于阈值的簇不进入昂贵的代码异味审查和语义判定阶段。

阶段2采用三组简洁指标验收。Embedding 检查候选—向量对齐、向量有限且非零、
形状与类型合同及重复运行确定性；聚类检查有效簇大小至少为2、逐仓覆盖率
50%～80%、最大簇占比不超过15%及跨文件复现；头部质量检查每仓Top100和
`Top100 ∩ Top20%` 的非平凡代表、源码变体、纯重复、强结构代理及代表AST规模。
当前正式结果的覆盖率为66.88%，平均簇大小为4.89，Top100非平凡代表率为
86.33%、纯重复率为12.78%、强结构代理率为40.12%，因此阶段2以“通过但保留
逐仓质量警告”结束。该结论只证明聚类输出是适合后续语义筛选的高质量候选集合，
不把所有簇直接认定为最终习语；这些验收参考线也不用于反向调参。

### 4.4 阶段3：多重可信门控

阶段3的处理单元是阶段2产生的**一个聚类簇**，目标不是执行一次宽泛的“习语判断”，
而是通过多证据语义精炼、受约束抽象、开放类型归属、复用价值评估和独立安全门禁，
把候选簇定型为可进入知识层的可信对象。实现包为保持简洁仍使用
`idiom_judgment`。完整流程为：

```text
单个仓库内归并后簇
  → 合同与确定性低价值规则
  → 高频低语义差异的规则抽象提案
  → 代表代码 + 词法去重变体 + 四项统计 + 规则/提案
  → LLM is_idiom + abstract/keep
  ├─→ 语义、类型与复用价值Agent ─┐
  └─→ 共享异味审查Agent ───┤
  → 业务评分与质量裁决 ────┘
  → 独立异味门禁
  → accepted / rejected
```

规则层拒绝支持数不足、代表或成员为空、簇规模与来源证据不一致、跨仓混合，以及
只包含裸 `break`、`continue`、`return` 等确定性低价值控制语句的簇。完全相同
源码、只在一个文件出现、缺少源码变体和 Parser 诊断只作为警告与审查证据，不由
单条启发式规则自动拒绝。这样既过滤合同错误和无意义样板，又避免把跨文件支持或
词法变化误写成习语的必要条件。

阶段3不再对所有特定元素执行 AST 反统一。抽象只针对“数量足够、结构角色稳定、
高频变化且对意图贡献低”的元素。工程初始规则要求至少3个结构对齐实例、同一
角色至少3个不同取值，并覆盖至少60%的簇成员；正式实验可在独立 pilot 后冻结
阈值，但不得用最终 IC、ISP、F1 或人工标签反复调参。局部声明变量的换名可形成
`<VAR_n>`，重复定义/使用必须共享绑定；低语义字面量可以形成 `<LIT_n>`。
调用名、类型、外部实体、控制条件、返回值、下标、格式字符串和
`0/1/-1/nullptr/true/false` 等哨兵默认保留，不能仅因实例不同就抽象。

阶段2冻结 DBSCAN 与阶段3之间增加不反向调参的仓库内保守归并。中心代码词法
等价时直接归并；AST同构且高相似的中心只有在所有差异均为已声明局部变量一致
换名时才归并。调用名、类型、运算符、字面量、控制条件、返回值和非局部标识差异
保持分离。合并后保留全部成员与来源信息，以全部原始 embedding 重算质心并选择
最近的真实代码。

规则只产生抽象提案，不直接修改代码。语义/抽象 Agent 必须接收代表代码、按
C++ 词法 token 去重的其他真实变体、原始成员数/变体数/文件数/源码位置数、
规则初判和所有提案，并显式返回 `is_idiom`、判断理由以及
`abstract` 或 `keep`。`abstract`
只能逐项批准输入中的 `proposal_id`，确定性代码再应用批准集合与规则提案的交集；
有效响应中的 `keep` 或无提案均保留代表代码，不会单独导致候选被拒绝；整份
语义/抽象响应在一次 JSON 修复和一次有界逻辑重试后仍失败时，保留原代码作为
审计证据，但语义与复用分安全降为0并拒绝。该 Agent 同时判断稳定意图、完整
边界、复用价值和前置条件，并采用受控目录与开放分类相结合的类型合同：能够与
已有 C++ 通用习语精确对应时输出具体类型，并归入目录化通用习语；无法可靠对应
但仍满足仓库内重复和有效性门禁时输出 `仓库特有习语`，并归入仓库专属习语，
不得强行套用相近类型。专属类别相对于当前目录版本成立，也包括可能具有一般意义
但尚未被目录总结的不常见习语；这类记录在目录版本迁移前不得跨仓库合并。受控目录以
Sutton 等对 C++ 泛型库习语的研究[E003]、社区目录 *More C++ Idioms*[E025]、
Coplien 专著[E111]及 C++ Core Guidelines[E112]为分类基础，并以 cppreference
的 RAII 与 Rule of Three/Five/Zero 页面[E113][E114]和 Boost.Scope Scope
Guards 文档[E115]收紧资源生命周期、特殊成员函数与作用域清理边界；这些资料
不构成封闭世界，也不提供本方法效果证据；
共享异味 Agent 按固定分类检查资源/内存生命周期、异常与错误处理、并发、未定义
行为、危险接口、控制流、耦合等风险，返回结构化 findings 和审查理由；风险分和门禁由
确定性代码计算。两个专项 Agent 并行且互不读取对方结论。阶段3业务总分为
`0.20 × 规则分 + 0.45 × 语义分 + 0.35 × 复用分`。最终由两类互不抵消的
门禁裁决：

- 规则失败、`is_idiom=false` 或语义/复用价值低于50：`rejected`；
- 通过硬门禁且总分至少70：`accepted`；
- 业务分不足、证据冲突或业务响应失败：`rejected`；
- 异味风险分不低于60或异味分析失败：独立 `smell_gate` 覆盖业务结论为
  `rejected`。

阶段3和阶段4统一采用调用级失败恢复：每个 Agent 的每次逻辑尝试只允许一次
JSON 修复，修复耗尽或请求异常后最多再执行一次逻辑尝试。仍失败时记录尝试数、
失败类型和回退动作；阶段3拒绝当前簇并继续后续簇，阶段4按依赖关系跳过当前组
尚未开始的下游 Agent。并行的语义/异味或质量/异味分支互不取消，技术失败不能
伪装成正常业务拒绝、无异味或无需合成。

完整成员与来源信息继续支撑本地规则、支持度、审计、评价和实例归类，但不进入
阶段3 LLM 请求；经哈希验证的代表上下文也只用于本地门禁和审计。阶段3输出保留
规则证据、全部抽象提案、精简语义请求、四项簇统计、`is_idiom`、
`abstract/keep` 决策、
批准集合、`abstraction_applied`、代表实例、完整成员与来源、语义/复用价值、
前置条件、通用目录或仓库特有习语分类、各 Agent 判断理由、业务评分、精简异味审查输入、
分类 findings、独立 `smell_gate` 和裁决理由。
对阶段3最终接受的候选，可抽象者以抽象模板进入阶段4，其余以未修改代表代码进入。

### 4.5 阶段4：关联闭环融合

阶段4的处理单元是代表仓库、源码路径和函数/区域范围完全一致的**多个候选习语**，
目标不是执行一次普通代码拼接或单轮“习语合成”，而是通过区域关系规划、受证据
约束的代码组装、当前结果重新定类和独立异味重审，使融合结果相对独立习语产生
明确且可审计的质量增益。`loc_label`、其他簇成员位置、
跨区域共现或 embedding 相似度都不能扩大分组；缺少可验证代表范围的候选不进入
融合组。实现包为保持简洁仍使用功能语义名
`idiom_synthesis`。阶段3的 `accepted` 产物是正式输入。阶段2簇到内部
`IdiomCandidate` 的统一适配和更严格门槛仅用于验证后备设计在 Schema 与
确定性逻辑上成立，不启动阶段4 Agent，也不产生实际合成结果。

```text
阶段3 accepted → 完全相同代表 project/path/extent 分组
                                  ↓
                       自动代表区域上下文
                                  ↓
                           合成规划Agent
                                  ↓
                           代码组装Agent
                                  ↓
                     质量复审Agent ─┬─ 共享异味审查Agent（独立重审）
                                    ↓
                     语法/上下文/新增调用确定性门禁
                                    ↓
                  accepted / rejected 合成增量

阶段2 clusters → 合同适配与严格阈值断言 → 停止，不执行 Agent
```

#### 4.5.1 自动上下文与关系规划

编排层在调用 LLM 前自动读取候选来源指向的同一函数范围，并校验仓库身份、路径
边界与文件内容哈希；不得向 LLM 提供任意文件或整个项目。上下文不可得或校验失败
时直接拒绝该次合成，且不产生 LLM 调用。

合成规划 Agent 从同一区域候选中选择至少两个真正互补的习语，输出合成目标、
顺序约束、共享绑定、上下文使用和预期质量增益。关系依据包括同一局部实体、
显式Def-Use、获取—释放/API配对、控制或异常区域，以及稳定源码顺序。找不到
至少两个具备这些关系的候选时停止；不因候选存在或 embedding 相似就强行合成。
规划和组装 Agent 也分别保存选择依据和代码组装依据，为质量复审提供信息并支持
后续人工审计。

#### 4.5.2 代码组装、复审与门禁

代码组装 Agent 只执行已经批准的计划。它可以保留、排序、去重和统一占位符，
也可以在计划允许且上下文中能定位证据时补入缺失的检查、清理或控制骨架；不得
添加输入习语和已核验上下文都不存在的调用、依赖或业务操作。

质量复审 Agent 检查所有来源意图、数据绑定、前置条件和职责是否保留，判断当前
合成结果是否仍属于代码习语、合成是否比简单拼接产生明确增益，并重新输出具体
通用类型或 `仓库特有习语` 及判断理由，不能直接继承来源阶段3类型；共享异味
审查 Agent 直接复用阶段3同一输入输出
合同、分类和阈值，并通过 `related_examples` 接收已验证函数上下文与来源习语，
对当前合成代码重新独立检查是否传播或引入反模式。两个复审并行。业务确定性门禁至少
检查：

- 将模板占位符替换为哑元后，Tree-sitter 直接或函数包装解析无错误；
- 新增调用目标来自来源习语或允许上下文；
- 编排层已提供通过校验的函数上下文；
- 质量复审确认意图保留且没有不受支持的新增内容。

阶段4业务分直接采用质量复审分。正式阶段3输入接受门槛为70；阶段2非执行合同
分支保留门槛80的离线断言。异味不进入业务分；风险分不低于60或
异味分析失败时由独立 `smell_gate` 直接拒绝。合成失败
不会删除原始习语，只保存可追溯的拒绝证据。阶段4 artifact 是
`synthesis_delta`：只保存合成尝试及成功增量，不复制单例、未选择或未成功合成的
阶段3习语；完整基础集合始终由阶段3 `accepted` 持有。最终增量对象包括合成模板、来源习语、
来源阶段3理由和类型、自动上下文证据、计划、组装来源、当前合成结果的
`is_idiom` 与习语类型、各 Agent 理由、质量分、异味审查输入/分类发现/独立门禁、确定性验证、
支持度与完整来源。可信编译信息可得时可以增加 `clang++ -fsyntax-only`，但不
执行链接或运行，也不能把 Clang 可用性设为全量流程门槛。

阶段3基础集合与阶段4合成增量共同进入最终知识组织层。`cataloged` 记录以
`taxonomy_version + catalog_id` 形成目录化通用视图，可在各仓库独立完成挖掘后
跨仓库统计和复用；`repository_specific` 记录以项目和阶段内记录身份形成仓库
专属视图；二者并集形成全量联合视图。联合分析不得抹去类别、目录版本、项目和
来源证据。

## 5 实验设计

### 5.1 实验对象

正式实验使用阶段2质量筛选后冻结的 23 个 C++ 开源仓库及其固定 commit，清单
和逐仓证据以
`docs/research/cpp-dataset-manifest.json` 为准。Parser 不要求固定目标项目编译器
或构建选项，因为零构建路径不执行项目构建；必须固定的是 CodeIdiomMine/Parser
版本、文件过滤、源码 commit、候选 profile、tokenizer 和后续方法参数。

数据集采用有明确约束的目的性最大差异抽样：候选阶段检查生产真实性、C++主体、
许可、活动性、标准源码入口以及领域与规模互补性，阶段1审查零构建可复现性，
阶段2再以冻结聚类指标和具体簇语义排除不适合进入LLM的聚合副本或单文件主导
项目。正式23仓按核心用途划为5个互斥主领域，并以阶段1的有效代码行、核心文件
和候选数平均秩划为低8、中8、高7三个相对分析复杂度层。分类合同与选择漏斗以
`docs/research/cpp-dataset-classification.md` 为准；分类不参与方法参数或阈值
选择，复杂度也不解释为代码质量或软件本质复杂度。

每个仓库使用全部合格源码独立完成
`Parser → fragments → embedding → DBSCAN → 判断 → 合成`。不同仓库的候选、
向量和簇不得合并，也不按文件或模块切出训练、开发、测试区域。只有最终指标计算
才按来源位置形成确定性的参考分区和测量分区；该分区不回溯重新运行发现流程。

### 5.2 对比方法

评价分为端到端主对比、CIMAS-CPP内部消融和部署降级三层。端到端主对比只保留能够从同一仓库完整合格源码独立产生习语模板的方法；阶段特有指标不参与主方法排名。

#### 5.2.1 端到端主基线

1. **Haggis-CPP。** Haggis把习语定义为带元变量的重复AST片段，以非参数贝叶斯概率树替换文法（DP-pTSG）学习能够解释训练语料的常见结构。原论文指出其统计方法原则上与语言无关，只要求目标语言能够提供语料和AST；但原实现使用Eclipse JDT及Java专用入口，因此本文实现的是面向C++的算法复现版本，而不是直接运行原Java工具[E002]。复现入口为[Haggis论文原文（作者主页PDF）](https://homepages.inf.ed.ac.uk/csutton/publications/idioms.pdf)和[原作者公开实现 `codemining-treelm`](https://github.com/mast-group/codemining-treelm)，工程实现固定参考commit `8b241a195fe860713c8dbbee387710533b97258c`。当前可运行版本使用Tree-sitter C++函数AST森林，保留PCFG基分布、DP后验预测、逐点collapsed Gibbs与burn-in后片段累计；逐点采样器是原仓库已有算法，但未复用原命令的type-blocked混合加速，也未复用JDT property binarization。标识符和字面量按Tree-sitter节点类别抽象。当前输出投影还只保留函数/块/语句根且 `ast_num >= 5` 的评价候选，该限制不是Haggis原方法，正式实验必须披露或做敏感性分析。该基线不使用Embedding、聚类、依赖增强、LLM判断、代码异味审查或习语合成；每次实验必须保存解析器、符号编码、采样器和后处理差异清单。
2. **LLM-Direct-Budget。** 该基线不使用AST/CFG/L-CSDC、Embedding、聚类、选择性抽象或多Agent编排进行发现。当前仓库的完整合格函数只按固定token上限机械分块并分配 `evidence_id`；第一轮由同一个LLM直接输出模板、意图、置信度和逐字源码证据，第二轮仍由同一LLM归并同义候选。主实验使用与CIMAS-CPP相同的基础模型和总输入输出token预算。预算统计包含system prompt、JSON Schema、业务输入和实际输出；模型完成发现后，公共评价适配器才把逐字证据映射回AST来源位置。本文不再把 `LLM-Direct-Full` 列为第四条baseline；若未来执行，只能作为不参与主排名的成本敏感性补充。
3. **Rules-Embedding-Clustering。** 使用当前Tree-sitter规则候选、代码Embedding和DBSCAN聚类，但不调用LLM判断、Agent编排或习语合成；合格簇直接视为习语种类。该方法固定执行组合截断：先过滤小于 `min_cluster_size` 的簇，再按簇大小降序、标签稳定打破并列，按预注册固定值或只依赖仓库内聚类支持度分布的无监督规则确定 `selection_ratio`，最后施加每项目 `max_types=100` 的数量上限。比例必须小于1，100只是最后的硬上限而不是固定Top100输出。该方法既是独立baseline，也是完整方法的“仅规则分析+嵌入聚类”端点消融。
4. **IdioMine-CPP。** 原IdioMine从Java方法构造精简DvCFG，以Data-driven Control Chain（DCC）抽取子习语，使用GraphCodeBERT和DBSCAN形成簇，再关联同函数子习语并由ChatGPT合成和判断[E006]。由于Java DvCFG与精确DCC不能直接迁移到C++，本文以Parser的 `semantic_def_use + def-use-v1` 局部Def-Use片段近似DCC，复用明确记录模型名的预训练代码Embedding，并在每个仓库内独立执行余弦DBSCAN。随后对每个非噪声簇执行一次相互独立的ChatGPT判断；只把代表位置的 `project + file + function_extent` 完全相同视为同一区域，对其中至少两个判断通过的习语尝试一次ChatGPT合成，合成成功后直接作为习语，不执行合成后复审。最终集合是全部独立判断通过项与全部成功合成项，不执行Top-K。该方法必须写作 `IdioMine-CPP`，不能简称为完整IdioMine复现。实现分析固定参考[原论文](https://doi.org/10.1145/3597503.3639135)和[作者公开仓库](https://github.com/Yanming-Yang/idioMine) commit `b9961c9fe85203eff16351d470b11b381572467f`。
5. **CIMAS-CPP。** 使用本文完整四阶段方法，作为待评价方法而非基线。当前工程中的聚类Top100模拟产物只用于评价器公式验证，不能代表CIMAS-CPP。

#### 5.2.2 公共输出契约与公平控制

所有主方法必须从同一仓库的完整合格源码独立输出统一对象：参数化C++代码模板、占位符与绑定、至少一个仓库内来源位置、方法自身的支持度/置信度和排序。公共适配器只允许完成字段映射、统一解析测量、规范化哈希与精确去重，不能替基线补做语义合并、异味过滤、依赖分析或习语合成。对Haggis-CPP，适配器把pTSG片段直接序列化为占位符模板；对LLM-Direct，输出由固定JSON schema约束；对Rules-Embedding-Clustering，每个冻结簇直接对应一个习语种类并保留全部来源成员；对IdioMine-CPP，输出为全部独立判断通过的DCC-lite簇与全部成功的同区域直接合成项。

发现阶段不划分训练、开发和测试区域。Haggis的 `alpha`、最小支持和节点数，
LLM提示、总token预算及单次响应token上限，Rules-Embedding-Clustering的最小
簇大小/比例/数量上限，IdioMine-CPP的Embedding模型、`eps` 与
`min_samples`，以及CIMAS的聚类与筛选阈值，均应依据论文来源、固定资源
预算、独立 pilot 或预注册无监督内部规则在正式运行前冻结；不得根据最终参考/
测量指标或人工标签调参。Haggis、LLM-Direct、IdioMine-CPP和CIMAS均
保存各自全部有效输出，不施加习语种类数量截断。

自动指标在每种方法按预注册配置运行并精确去重后的完整输出集合上计算。人工评价在实验前根据统一标注预算设定每仓库最大 $K$，各方法按自身原生分数取Top-$K$，并在指标名中标注 `@K`；若各方法输出均不超过预算，则Top-$K$自然等价于全量核验。方法不足 $K$ 个结果时不得补齐。跨方法规范化后完全相同的模板合并成一个盲法标注项，标签复用于所有产生该模板的方法，以减少重复人工工作。

#### 5.2.3 核心消融与降级实验

端到端主表中的 `LLM-Direct-Budget` 与 `Rules-Embedding-Clustering` 同时提供两条粗粒度端点消融：前者只保留LLM直接推理，后者只保留确定性候选分析、Embedding和聚类。它们用于回答“仅LLM”和“无LLM的规则/表示学习流水线”能走到哪里；下表继续保留CIMAS内部的细粒度模块消融，不能把同一运行重复统计为两种证据。

| 变体 | 主要变化 | 回答的问题 | 实验层级 |

| `CIMAS-Fixed3Level` | 保留语句/区域/函数候选，关闭L-CSDC | 轻量非连续依赖增强是否带来独有收益 | 阶段1消融 |

### 5.3 评价框架与指标

本研究不构造“整个代码仓库中全部真实习语”的Ground Truth，也不计算全仓习语Recall。为使Haggis-CPP、LLM-Direct-Budget、Rules-Embedding-Clustering、IdioMine-CPP、各细粒度消融和CIMAS-CPP能够公平比较，所有端到端方法必须先通过当前固定九指标合同；论文层若增加人工或成本指标，应另行冻结且不得改写工程评价器的既有公式。

#### 5.3.1 全自动公共指标

为与Haggis、IdioMine及CIMAS历史结果比较，所有方法首先在完整去重输出集合上计算以下指标：

- **Raw Idiom Coverage（Raw-IC）**：全仓发现结束后，测量分区函数中被任一参考习语变体匹配的AST节点并集占比。重叠节点只计一次，并同时报告函数宏平均和节点微平均；工程最终值固定为二者算术平均。
- **Raw Idiom Set Precision（Raw-ISP）**：参考分区中有来源实例的习语种类里，在测量分区至少复现一次的比例。它表示仓库内分区复现性，不是人工正确率或未知数据泛化。
- **Raw-F1**：工程最终 Raw-IC 与Raw-ISP的调和平均，只表示仓库内覆盖—复现平衡。
- **Average AST Size（AvgAST）**：模板使用仓库内代表实例回填后包含的AST节点数；同时报告中位数和四分位距，无法回填/解析的模板计入IV失败但不从输出数中删除。
- **Output Yield（OY）**：每万行有效C++完整仓库代码产生的去重输出模板数，防止只比较比例而忽略方法实际产量。
- **Instantiation Validity（IV）**：用方法提供的仓库内证据回填占位符后，能够恢复匹配AST并由Clang重新解析的模板比例。可用编译上下文中的 `clang++ -fsyntax-only` 通过率另列，不强迫缺失构建配置的模板进入不公平分母。
- **End-to-End Cost（Cost）**：每万行代码的墙钟时间、峰值内存、CPU/GPU时长、LLM输入/输出token和按调用时价格计算的费用。非LLM方法的token与API费用记为0，不把不同资源强行压缩成一个不透明总分。

设测量分区函数 $f$ 的可统计AST节点为 $N_f$，完整仓库习语集合中具有参考实例的子集为 $I_{ref}$，其在函数中匹配到的节点并集为 $M(f,I_{ref})$，则IC、ISP与F1按当前工程口径计算：

\[
IC_{macro}=\frac{1}{|F|}\sum_{f\in F}\frac{|M(f,I_{ref})|}{|N_f|},\quad
IC=\frac{IC_{macro}+IC_{micro}}{2},\quad
ISP=\frac{|\{i\in I_{ref}\mid i\text{在测量分区复现}\}|}{|I_{ref}|},\quad
F1=\frac{2\cdot IC\cdot ISP}{IC+ISP}
\]

当分母为空或IC与ISP均为0时，对应指标记为0。统一评估器只执行预先冻结的测量与来源映射；这不算向Haggis、LLM-Direct、Rules-Embedding-Clustering或IdioMine-CPP补做发现能力。当前工程的正式口径以 `docs/guides/evaluation-metrics.md` 为准：逐项目、仓库宏平均和全局层都必须能计算 `IC_macro`、`IC_micro`、`IC`、`ISP`、`F1`、`idiom_type_count`、`avg_cluster_size`、`avg_cross_file_support` 和 `AvgAST`。IC与ISP沿用Haggis及CIMAS历史评价思路[E002][E001]；CIMAS历史ANI1/ANI2仅表示两个下游任务的AST节点增幅，不进入端到端习语挖掘主表[E001]。[CIMAS-PAPER, p.2]

#### 5.3.2 最小人工核验与质量校正

人工工作只核验Top-$K$盲评池中的最终模板，不从源码中寻找漏掉的习语。每个跨方法精确去重后的模板只标一次，最小标签为：`valid_idiom`、`invalid_idiom` 或 `context_dependent`，以及是否含应阻止复用的严重代码异味。无效原因记录为意图不清、边界不完整、机械样板/过度特化、语法逻辑错误或严重异味。异味指南区分论文证据、固定版本 Clang-Tidy 工具规则和注明访问日期的 SEI CERT C++ 技术标准，任何规则命中均不自动成为人工真值[E028][E109][E110]。两名C++标注者独立评价，隐藏方法名称、原生分数和Agent结论，分歧由第三人裁决；报告Cohen’s Kappa、标注数量和用时[E095]。代码完整性、语义清晰度和泛化性的1—5分评价降为可选的分层定性分析，不再要求对所有输出评分。

人工标签只产生两个直接主指标：

\[
HVIP@K=\frac{|I_{valid}@K|}{|I_{out}@K|},\qquad
ALR@K=\frac{|I_{severe\_smell}@K|}{|I_{out}@K|}
\]

其中HVIP@K衡量Top-$K$输出中人工确认习语的比例，ALR@K衡量反模式泄漏。上下文依赖项在保守HVIP@K中不计为有效，并单独报告未决率。若全部输出少于 $K$，则对全部输出计算并注明“all”；若没有输出，HVIP@K记为不适用，其他产量和覆盖指标记为0。

同一组人工标签还可自动派生质量校正指标，无需新增标注：只用人工确认集合重新运行统一匹配器，得到 **V-IC@K、V-ISP@K和V-F1@K**；并计算 **Validated Idiom Yield（VIY@K）**：

\[
VIY@K=\frac{|I_{valid}@K|}{\text{有效C++完整仓库代码行数}/10{,}000}
\]

Raw指标回答“方法自动输出了多少、覆盖和复现如何”，V指标回答“确认有效的那部分实际覆盖和复现如何”。二者必须并列报告，不能只展示对本方法更有利的一组。

#### 5.3.3 方法内部诊断与指标删减

以下指标不要求所有baseline计算，也不进入端到端主排名：阶段1报告自动化的BCR、PPR、抽取时间与内存，分层抽样的 $EVY_{sample}$，以及轨道B独有的人工确认非连续增量VNG；阶段4通过 `NoSmell` 消融的ALR@K变化验证异味审查贡献，并仅在按阶段、过滤结果、分析失败和类别分层抽取的审计样本上报告总体及分阶段CS-P/CS-R/CS-F1、Accuracy、误过滤率、漏报率和逐类别P/R/F1。不设置留一仓库 CRM 指标。

原计划中的DEP/DER、SD-F1、SL-F1和SRR不再列为论文主指标：它们分别需要额外边级或模块级真值，且Haggis与LLM-Direct无法对应计算。若实现调试确有需要，可保留在附录或日志中，但不得扩张人工标注任务。最终端到端主表固定为两组：自动组 `Raw-IC、Raw-ISP、Raw-F1、AvgAST、OY、IV、Cost`；人工及派生组 `HVIP@K、ALR@K、V-IC@K、V-ISP@K、V-F1@K、VIY@K`。

### 5.4 参数与实现记录

正式实验需记录逐仓完整语料 manifest、最终参考/测量分区算法、AST纳入节点表、统一模板schema、匹配规则、精确去重规则和全部指标分子分母。Haggis-CPP额外记录原代码版本、C++适配差异、Tree-sitter AST到采样树映射、符号抽象规则、MCMC迭代与burn-in、`alpha`、最小支持和最小节点数；LLM-Direct记录机械分块、map/reduce prompt、模型版本、温度、随机种子、总token预算、单次响应token上限、实际输入输出token和失败修复；Rules-Embedding-Clustering额外记录候选规则、Embedding/DBSCAN版本、最小簇大小、比例截断前后数量和种类上限；IdioMine-CPP记录原论文与作者代码commit、DCC-lite候选版本、实际Embedding模型、DBSCAN参数、非噪声簇数、判断/合成prompt与schema、精确同区域分组、模型、调用/token用量和全部简化操作；CIMAS-CPP记录Clang/Tree-sitter版本、编译数据库覆盖率、能力掩码、L-CSDC预算、DBSCAN改进贝叶斯目标、硬约束、搜索空间、warm-start观测、最佳已观测参数、各Agent prompt/schema和回流上限。只有规则baseline存在最终习语种类截断。

所有方法统一保存完整输出、原生排序分数、Top-$K$子集、仓库内代表证据、重新解析/语法验证日志、墙钟时间、峰值内存、CPU/GPU时长、LLM token及费用。人工侧保存跨方法去重映射、盲法标签、标注时长、一致性和裁决记录。主流程及所有baseline均不得依赖动态执行、运行时插桩或项目动态链接环境。

### 5.5 实验执行与统计分析

端到端比较先在每个仓库内独立计算指标，再报告仓库宏平均，避免Envoy等大型仓库支配结论；节点微平均只作补充。确定性方法至少完整运行一次，含随机采样、聚类或LLM的方法使用不少于三个固定随机种子，报告均值、标准差和全部失败运行。LLM-Direct-Budget与CIMAS-CPP使用相同基础模型，并以实际输入加输出token校验预算差异，不能只以预估上限宣称预算匹配。

对Raw-IC、Raw-ISP、Raw-F1、IV等自动指标，以文件或克隆族为重采样单位计算配对bootstrap 95%置信区间[E076]；对HVIP@K、ALR@K等比例报告分子、分母及Wilson 95%置信区间[E092]。多方法比较先进行总体检验，再对预注册的“CIMAS-CPP对Haggis-CPP”“CIMAS-CPP对LLM-Direct-Budget”“CIMAS-CPP对IdioMine-CPP”和核心消融差异执行配对比较，并用Holm方法校正多重检验[E022]。除显著性外必须报告绝对差值和相对成本，不构造把覆盖、质量和费用任意加权的单一总分。

主分析使用全部23仓的逐仓结果和仓库宏平均；附加分析分别按主领域和相对分析
复杂度复算类别内仓库宏平均、成本与失败率。主领域每类只有3～6仓，二维
“领域×复杂度”还存在空单元，因此分层结果以效应量、区间和描述性趋势为主，
不替代总体结论，也不把稀疏单元作为完整双因素因果实验。所有方法继续对同一仓库
使用相同配置，类别标签只在逐仓指标完成后参与汇总。

## 7 案例分析

### 7.1 RAII锁管理习语

RAII 将资源生命周期绑定到对象生命周期，C++ Core Guidelines 与 cppreference
分别提供资源管理规则和语言语义边界[E112][E113]。因此，该案例按生命周期合同
识别，不以 `lock_guard` 这一 API 名称单独决定类型。

示例模板：

```cpp
{
    std::lock_guard<<TYPE_1>> <VAR_1>(<MUTEX_1>);
    <BLOCK_1>
}
```

该模板表达“在词法作用域内持锁并自动释放”的意图。合法性条件包括 `<MUTEX_1>` 与 `<TYPE_1>` 匹配，且 `<VAR_1>` 生命周期覆盖 `<BLOCK_1>`。相比仅挖掘构造语句，区域级模板保留了作用域边界。

### 7.2 资源获取与失败清理习语

```cpp
auto <VAR_1> = <CALL_1>(<EXPR_1>);
if (<VAR_1> < 0) {
    return <ERROR_1>;
}
// ...
<CALL_2>(<VAR_1>);
```

此类模板必须通过数据依赖确认获取、检查和释放操作使用同一资源变量。若项目可使用
RAII 或 Scope Guard 替代手工释放，共享代码异味审查 Agent 应结合语言标准、
项目约定和代表实例输出对应类别、严重度、置信度与证据，由确定性风险算法和独立
门禁裁决，而不是无条件视为最佳实践。Boost.Scope 文档用于核对作用域退出、成功
与失败分支上的清理语义[E115]；涉及资源所有权的类型还需按 Rule of
Three/Five/Zero 检查复制、移动和析构契约[E114]。

### 7.3 高频但非习语的反例

单独的日志语句、默认构造函数、空异常处理和机械字段赋值可能非常高频。代码异味审查Agent应将空异常处理等明显反模式作为拒绝证据，语义/复用价值Agent则应将缺少独立意图的机械样板作为拒绝证据；结构和绑定由确定性规则与解析器检查。裁决记录保留各专项理由，使“有风险”和“没有复用价值”不会被混成同一种拒绝原因。

## 8 讨论

### 8.1 为什么限定为C++

本文限定 C++，以 Tree-sitter/C++ Adapter 保证源码可得即可解析，并在安全可得时利用 Clang 的类型、符号、宏和模板信息。完整编译环境不是任何基础候选的必要条件；Clang 增强失败也不改变原文 AST、诊断和三层基础候选。研究比较的是同一 C++ 任务中零构建基础能力与可选语义增强的差异，不开展多语言实证。该设计不仅使习语产物可复用，也使挖掘方法能够跨构建系统、平台和依赖状态复用。

### 8.2 高频、优质与仓库内复现的关系

高频表示模式在当前仓库中重复，优质表示模式具有清晰意图且不含明显缺陷，仓库内复现表示模式跨文件或在参考/测量分区间再次出现。三者相关但不等价。本文用频率发现候选，阶段3再由语义/复用价值与代码异味两个专项Agent分别评估意图、复用价值和潜在风险，结构合同由确定性规则与解析器负责，最后用全仓发现后的参考/测量分区评价仓库内复现性。代码异味审查不是为了把所有非主流写法一律删除，而是阻止有可解释风险的坏习惯被系统自动放大；同样，通过异味审查也不能替代习语语义与复用价值判断。

### 8.3 大语言模型的角色边界

大模型不负责仓库全量扫描、AST构建或最终合法性证明。阶段3的语义/复用价值Agent提供业务分和证据，共享异味Agent只提供分类 findings；业务分与确定性异味门禁独立裁决。阶段4由编排层自动加载上下文，合成规划、代码组装和质量复审Agent只处理同一区域候选，异味审查复用阶段3的同一合同，但针对合成结果重新运行，并接受确定性语法、来源和新增调用检查。职责隔离的目标是减少一个模型在同一上下文中自我确认，而不是把多个Agent的共识当成事实；解析器与可选 `clang++ -fsyntax-only` 仍提供不可被LLM覆盖的确定性证据，低分、冲突或响应失败均自动拒绝。

### 8.4 工程应用

习语库可以作为 IDE 推荐、代码审查、测试生成、规范识别和新成员培训的知识来源。
目录化通用习语适合按稳定类型跨仓库检索与复用；仓库专属习语优先服务本项目，
并保留“尚未目录化”的候选地位；全量联合视图用于总体检索与分析。实际部署还需
维护目录版本、来源项目、适用前提、语言标准、最小依赖和废弃状态，防止旧习语随
项目演化变成不推荐实践。

## 9 有效性威胁

### 9.1 内部有效性

- 聚类和LLM参数可能影响结果；应固定配置并重复实验；
- Tree-sitter按名称与作用域近似Def-Use，可能混淆遮蔽变量；必须与Clang符号绑定结果抽样比较；
- L-CSDC触发器和两跳预算可能漏掉较长习语或引入无关语句；由于不存在全仓习语真值，只报告分层抽样的 $EVY_{sample}$、最终输出中的VNG和预算敏感性，不宣称全仓召回；
- Clang编译数据库覆盖不完整会使部分文件缺少增强能力；应逐文件记录能力掩码，但不得影响 ZBP 基础结果；
- 代码异味常依赖项目约定和上下文，LLM审查 Agent 可能产生漏报或误报；应固定异味分类与提示，保留上下文，并用多专家标注集评价；
- Clang-Tidy 检查清单与 SEI CERT C++ 在线技术标准持续维护；实验必须冻结工具版本、启用检查、规则标识、访问日期和映射表，不能把网页后续变化混入既有结果[E109][E110]；
- 多个Agent若使用相同基础模型，错误可能相关；应使用职责隔离的prompt、隐藏其他专项结论，并以RuleOnlyJudgment、SingleSynthesizer和角色消融检验编排是否真正有效；
- 综合判定Agent可能越权重写专项结论，合成Agent也可能在反复修复中引入新逻辑；应采用机器可检验的裁决规则、限制合成输入和回流次数，并保存完整轨迹；
- 模板编译壳可能遗漏真实构建上下文；应同时在原仓库配置中验证；
- 最终参考/测量文件分区可能受仓库目录组织和近重复文件分布影响；应固定哈希规则，报告分区分母，并做文件/模块分层敏感性分析，但不回溯重跑发现流程；
- 模板匹配阈值、AST节点过滤和重叠匹配处理会影响IC/ISP；应在正式测量前预注册并公开计算脚本，不用最终指标反复调整；
- Haggis-CPP需要把Java/JDT实现迁移到Tree-sitter C++ AST，节点映射、逐点采样、函数级AST森林和节点类别抽象可能改变原算法行为；应发布适配差异、与原实现的小型Java sanity check及采样收敛诊断，不声称完全复现原结果；
- LLM-Direct受函数机械分块、归并prompt和token预算影响；应固定分块顺序、记录实际端点usage并重复运行，不把超出预算的Full版本列入主baseline；
- Rules-Embedding-Clustering受DBSCAN塌缩簇和组合截断影响；应使用预注册固定值或聚类内部无监督规则确定最小簇大小、保留比例与数量上限，并报告每一步截断前后数量；
- IdioMine-CPP只近似DCC的数据依赖部分，省略Java DvCFG控制依赖与原作者的同函数字符串关联，当前缓存向量使用UniXcoder而非原方法GraphCodeBERT；ChatGPT层也简化为逐簇独立判断和同区域一次合成，成功合成后不再复审。应始终使用完整方法名、发布差异清单、prompt、参数与调用成本，不把该简化迁移解释为完整IdioMine复现；
- Top-$K$可能偏向各方法原生排序较好的结果；应在人工核验前固定K，另报告完整输出的自动指标和多个K值的敏感性，不能只选择最有利的K；
- 人工标注可能带有个人风格偏好；应提供统一指南、隐藏方法与Agent结论、报告标注时长和一致性，并保留第三人裁决记录。

### 9.2 外部有效性

- 正式仓库采用目的性最大差异抽样而不是概率抽样，不能代表全部C++项目；主领域
  是当前研究的操作性目录，跨领域项目的互斥归类也可能影响分层结果。应公开细粒度
  `project_type`、`idiom_focus`、逐仓结果和替代分组敏感性，不把类别差异直接
  外推到GitHub C++总体；
- 相对分析复杂度来自当前23仓内的代码行、文件和候选平均秩，只描述流水线处理
  负荷，正式集合变化后会重新计算；不得解释为代码质量、维护难度或软件本质
  复杂度；
- 企业项目的宏、框架和编码规范可能与开源仓库不同；结论不应无条件外推。

### 9.3 构念有效性

- IC衡量测量分区AST节点覆盖，ISP衡量参考习语在同一仓库测量分区的复现；二者及其F1不能单独证明习语“好”，不能替代全仓召回或人工正确率，也不能解释为未知仓库泛化；
- HVIP@K只评价被选入统一盲评池的输出正确性，不覆盖仓库中未被发现的习语或Top-$K$之外的长尾；VIY@K用于约束输出过少问题，但也不能代替完整输出上的Raw覆盖与复现；
- BCR只能证明候选规模得到保留，$EVY_{sample}$只说明抽样增强边界质量，VNG只说明轨道B对最终人工确认结果的可观测增量；三者均不能证明潜在习语已被完整发现；
- ALR@K依赖人工异味分类和严重度阈值；应报告类别级结果、误过滤率和标注一致性，不能把风格分歧都当作反模式；
- AvgAST、NSR和ANI只能作为结构规模或下游代码增幅统计，不能直接代表语义完整、功能正确、测试质量或规范识别准确率。

### 9.4 结论有效性

- 正式结果需报告样本数、方差、置信区间和适当的显著性检验；
- 多次比较应控制偶然显著性；
- mock数据仅用于规划，不能进入最终统计推断。

## 10 结论与未来工作

本文研究一种兼顾创新性、候选产量和实现成本的 C++代码习语挖掘方法，并将其固定为四阶段流水线：阶段1以双轨抽取保留语句、区域和函数三类基础候选，并用选择性L-CSDC补充有限的非连续静态依赖候选；阶段2执行结构—语义嵌入、密度聚类和冻结结果上的仓库内保守归并；阶段3“多重可信门控”先用完整成员规则筛出可能抽象的位置，再让语义/抽象 Agent 基于代表代码、词法去重变体、四项统计和规则证据决定抽象或保持原样，同时执行语义/复用价值业务评分、类型分类和共享异味独立门禁；阶段4“关联闭环融合”正式消费阶段3已定型产物，自动加载代表区域上下文，再对同一区域多个习语执行关系规划、代码组装、当前结果复核和重新分类，并以同一异味合同对融合结果重新独立审查。阶段2到阶段4只保留非执行合同适配。只有业务质量过门且未触发异味门禁的结果才进入知识库，异味过滤另由分层人工审计验证。最终知识库以受控目录把已接受记录组织为可跨仓库聚合和复用的目录化通用习语，以及保持项目作用域的仓库专属习语，同时保留二者并集的全量联合视图；尚未目录化的不常见通用习语在当前版本下归入后者。Tree-sitter/C++ Adapter 提供覆盖全量语料的零构建基础路径，Clang提供可选的语义精度增强。端到端实验固定比较Haggis-CPP、LLM-Direct-Budget、Rules-Embedding-Clustering、IdioMine-CPP和CIMAS-CPP；其中LLM-Direct-Budget与Rules-Embedding-Clustering分别提供“仅LLM”和“仅规则分析+嵌入聚类”的端点消融，IdioMine-CPP提供前身方法“核心挖掘、独立判断、同区域直接合成”的C++简化迁移，LineOnly、Fixed3Level、SemanticOnly、NoSelectiveAbstract、RuleOnlyJudgment、NoSmell、NoContext、SingleSynthesizer和NoSynthesis继续回答细粒度模块贡献。工程复现首先保证五种方法共享固定九指标合同；论文层的附加人工、静态有效性和成本分析必须另行冻结，且不得把规则baseline的合成产物截断改写成评价指标或套用到其他方法。

后续工作首先是以真实代码和日志替换全部 [MOCK] 数据，完成专家标注和消融实验；其次研究习语随仓库版本演化的增量更新；最后探索习语在IDE推荐和自动代码审查中的应用。上述扩展仍限定于 C++，除非研究范围被用户重新明确修改。
