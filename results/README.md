# 全仓实验记录

本文是正式 23 仓主线方法、外部 baseline 与消融实验的唯一记录。仓库完成一个就追加一行；
LevelDB、Ninja、toml++ 是当前已完整运行的 3 个仓库，不建立独立的“三仓实验”概念。

## 2. 历史运行与修复结论

### 2.1 2026-08-01 初次 Stage 3/4 全量运行（作废）

初次运行使用 `gpt-5.6-luna`。Stage 3 完成全部 912 簇裁决，接受 135、拒绝 777，
技术失败为 0；Stage 4 对 58 个共现区域执行 60 次尝试，接受 14 条记录、拒绝 46 条，
技术失败为 0。两阶段共消耗 6,600,017 token，累计流水线耗时约 4.26 小时。

| 仓库 | Stage 3 接受 | Stage 4 接受记录 | 词法去重后最终习语 |

| LevelDB | 63 | 1 | 64 |

| toml++ | 31 | 11 | 37 |

该轮 Stage 4 会重复处理同一候选组合、对相同代码给出相反裁决，并把来源组件实例误作
合成习语实例，因此 Stage 4 结果和对应指标作废。此轮只作为缺陷发现记录，不用于任何
baseline 结论。

## 3. 当前主线最终结果

### 3.1 评价合同

- IC 分母在 Stage 3 裁决前冻结，只含 Stage 2 非噪声聚类成员精确映射得到的函数与 AST
  节点；同一节点只计一次。
- 分子为 Stage 4 最终 `accepted` 来源证据加参考折模板在测量折中的额外匹配，并与机会域
  取交集。
- `IC = (IC_macro + IC_micro) / 2`，不做平方根、对数或其他变换，`IC_raw == IC`。
- ISP 使用精确 `(仓库相对路径, 函数根 extent)` 支持域，同一函数重复只计一次。
- `F1 = 2 * IC * ISP / (IC + ISP)`。
- 五折按文件 round-robin 轮转，同一文件的函数不会跨参考折和测量折。
- `IC_generalization`、`ISP_generalization`、`ISP_fold` 和 `IC_all` 仅作更严格的敏感性
  证据，不替代主指标。

## 4. 外部 Baseline 与 Stage 2 质量消融

正式运行前冻结以下参数，不查看 baseline 的 IC、ISP 或 F1 后调参：

| 方法 | 冻结配置 |
|---|---|

| Stage2-Frequency-Ablation（质量消融） | `min_cluster_size=3`、`selection_ratio=0.5`、`max_types=100`；比例表示保留通过最小簇过滤后的前半部分，先于任何结果和人工标签观察固定 |
| LLM-Direct-Budget | `gpt-5.6-luna`、全局 token 上限 `7,142,524`、`chunk_tokens=3000`、`reduce_chunk_tokens=4000`、`max_output_tokens=2048`，不限制函数数；reduce 只机械压缩证据为稳定引用，不改变候选语义 |
| IdioMine-CPP | 复用实际 UniXcoder embedding，`eps=0.5`、`min_samples=2`、`gpt-5.6-luna`、全局 token 上限 `7,142,524`、`max_output_tokens=1024`、每簇最多 10 个示例 |

LLM 预算取产生当前主方法语义证据的严格运行总 token 与当前 Stage 4 重跑 token 之和，
属于对 baseline 有利的保守上界，避免低估主方法成本。三条外部 baseline 与质量消融复用第 1 节标准
产物、相同仓库范围、相同冻结机会域和同一评价器；新增仓库结果直接追加到本节，不另建
子集结果文档。

每个 baseline 至少记录方法与实现边界、输入层级、参数、是否调用 LLM、token/耗时、
每仓有效产量、IC、ISP、F1、严格敏感性指标、失败数，以及与主方法的同口径增量。若方法
无法产生与当前习语合同一致的输出，应记录适配规则，不得通过改变分母或支持域获得优势。

因此低 IC 表示当前 C++ 适配输出保守，不否定原 Java 方法。完整差异见
[baseline 指南](../docs/guides/baselines.md#23-java-原实验与当前-c-结果的解释边界)。

IdioMine-CPP 的低产量首先来自聚类前 DCC-lite 候选不足，而不只是最终判断严格：

| 仓库 | CIMAS Stage 2 嵌入候选 | IdioMine DCC-lite 候选 | DCC-lite 占比 | CIMAS 非噪声簇 | IdioMine 非噪声簇 | 最终习语 CIMAS / IdioMine |
|---|---:|---:|---:|---:|---:|---:|
| LevelDB | 3,072 | 105 | 3.4% | 455 | 7 | 126 / 5 |
| Ninja | 2,440 | 179 | 7.3% | 390 | 7 | 95 / 4 |

| 合计 | 6,235 | 299 | 4.8% | 912 | 18 | 268 / 9 |

两条流水线实际复用相同 UniXcoder 向量，主要差异在 embedding 之前：当前
IdioMine-CPP 只保留 `semantic_def_use` 局部 Def-Use 片段，没有复现原 Java DvCFG、
精确 DCC 和子习语关联；CIMAS 则以语句、区域、函数三层候选保底，并把 L-CSDC
作为增量。前者只有 299 个候选进入聚类，后者有 6,235 个，聚类算法无法补回已经遗漏的
C++ 控制流、错误处理、资源管理和完整区域候选。

在此基础上，IdioMine-CPP 的 `eps=0.5` 把噪声候选从旧试跑的 `86/132/13` 降至
`19/24/1`，但非噪声簇从 `7/20/1` 变为 `7/7/4`。较大邻域在 Ninja 中产生密度连通，
多个局部模式被合并成少量宽簇；当前每簇只输出一个判断对象，因此接受项仅为 `5/4/0`。
toml++ 虽恢复 4 个候选簇，审查仍发现簇内意图不一致并全部拒绝。缓存向量重放的簇内
平均余弦距离也显示 CIMAS 为 `0.057/0.054/0.042`，IdioMine-CPP 为
`0.131/0.145/0.161`，后者更松散。减少 DBSCAN 噪声因而不等于增加有效聚类或最终
习语。原版 Java DCC 的有效性与当前 C++ 简化迁移的边界见
[baseline 指南](../docs/guides/baselines.md#42-java-原实验与当前-c-结果的解释边界)。
LLM-Direct-Budget 的覆盖和 F1 高于 Haggis-CPP 与 IdioMine-CPP，但仍低于主方法；其
toml++ 习语类型最多，函数支持率却最低，说明直接 LLM 发现保留了较多低支持模式。

### 4.5 LLM-Direct 运行与恢复

正式运行完成 140 次 map 和 10 次最终采用的 reduce：LevelDB `42+3`、Ninja
`43+2`、toml++ `55+5`，对应 map 候选 120、82、189，最终习语 24、50、64。
端点请求总数为 166，本地近似输入输出用量 750,388 token，未耗尽 7,142,524 token
上限。端点数高于 150 次成功逻辑调用，是因为 JSON 修复、连接失败和归并格式稳定化前
已记账但未采用的请求也保留在成本审计中。

首次大输入 reduce 会被服务端断开，且旧实现不能恢复 map。修复后 map 以项目名和块号、
reduce 以项目名、层级和块号、项目完成状态以项目名即时写入 SQLite checkpoint；
数据集重排不会串仓。reduce 将完整源码证据机械替换为稳定引用，
使 LevelDB 同一批候选从 9 个完整证据块降为 3 个引用块。引用在最终产物中完整还原，
每块输出引用集合必须与输入完全相等；正式运行中 LevelDB 351、Ninja 204、toml++ 679
个引用均无遗漏。每层先做规范化模板去重并合并引用，再判断分块数是否减少；只有能够
继续压缩时才进入下一层，避免为了得到单块输出而形成隐式数量截断。预算不足时会保存
已消耗用量并把项目标为不完整，统一验证器拒绝不完整产物。正式结果完成后 checkpoint
和临时聚合数据均不作为可复用产物保留。
